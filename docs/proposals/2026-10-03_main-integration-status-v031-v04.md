## 2. 현재 파일과 배포의 소유

**현재 Site의 최종 배포는 두리만 수행한다.** 배포 직전에 소스·에셋 기준을 고정하고, 최신 원격 변경과 인수 결과를 확인한 다음 통합 QA를 거친다. 사용자의 이후 명시적 역할 변경이 있으면 그 결정을 따른다.

|---|---|---|
| P0 이어하기·저장 보호 | 두리 | 같은 운영 저장 파일을 동시에 수정하지 않는다 |
| P1 v0.3.1 음향과 v0.4 변경 통합 | 두리 | 소유가 겹치는 음향·UI 파일은 패치·근거로 인계한다 |
| 영웅 아트 후보 | 두리의 격리 통합 검토, 디자인의 에셋 제작 | 최종 외형을 자동 확정하거나 현행 아트를 덮어쓰지 않는다 |

개발1·2는 격리된 소스 사본, 테스트 도구, diff·패치와 산출물을 두리에게 전달한다. 현재 Site나 별도의 공개 배포를 직접 갱신하지 않는다. 다른 팀도 자기 역할의 승인 범위에서 독립 작업을 이어갈 수 있다.

이 기록은 이미 실행 중인 다른 Work를 자동으로 중지하거나 취소하지 않는다. 문서 게시만으로 상대가 읽고 작업을 멈췄다고 보고하지 않는다.

## 3. 같은 파일을 넘길 때 확인할 것

두리와 작업 담당은 변경 전에 작업 ID, 정확한 파일 경로, 기준 커밋, 격리 브랜치, 허용 변경과 인수 조건을 확인한다. 한 파일의 변경 담당은 한 명으로 둔다.

이미 같은 영역의 작업이 있으면 그 산출물을 보존하고 diff·테스트 결과부터 인계한다. 인계가 확인되기 전에는 상대 작업을 덮어쓰거나 현재 배포를 갱신하지 않는다. 과거의 “개발1 최종 통합” 설명보다 현재의 “두리 최종 통합·검수·배포” 역할을 따른다.
