## 현재 버전

실행 링크는 소유자의 최신 배포 메시지에서 확인한다. 기존 비공개 접근 범위를 유지한다.

SOURCE·WEB은 기존 항목을 이력 보존 방식으로 갱신했고 저장 후 실제 파일을 다시 내려받아 크기·SHA256과 바이트 일치를 확인했다. 소유자 전용 접근 범위를 유지했다. v0.1~v0.9의 기존 열 런타임 payload, 엔진·전송·저장 브리지는 바이트 그대로 보존했다. 배포 디렉터리에 게임 소스를 넣지 않았다. 최종 배포 아카이브의 모든 dist 항목을 다시 읽어 동결 manifest와 일치를 확인했다.

자세한 구현·검수·보존 기록은 [v0.10 배포 보고](proposals/2026-10-03_main-v10-release-integration-report.md)를 따른다. 이전 v0.9 전달물과 당시 검수는 [v0.9 보고](proposals/2026-10-03_main-v09-release-integration-report.md)에 보존했다. 소스·배포 커밋과 ZIP·PCK 해시는 서로 다른 식별자다.

## 같은 사용자의 소스 전달물

기존 SOURCE·WEB 항목을 갱신하고 이전 이력을 보존했다. 위 최종 영수증의 파일명·크기·해시로 승인된 같은 사용자 Library 또는 첨부의 실제 파일을 대조한다.

이 공개 저장소는 문서 자료실이다. 비공개 소스·에셋을 자동 업로드하지 않는다. 도구나 파일 접근이 없으면 현재 파일명·버전을 지정해 필요한 첨부를 요청하고 차단으로 기록한다. 비공개 실행·Library 링크·ID는 공개 문서에 넣지 않는다.

## 현재 기능과 역사적 기록의 구분

- v0.10은 이미 처치된 적의 어둡고 납작한 잔상을 일시정지하지 않은 실제 표시 시간 220ms 동안 남기는 작은 화면 피드백 변경이다. 최대 12개이며 오래된 잔상부터 지운다. 전장 안으로 자르고 살아 있는 적보다 아래에 그리며 HP·상태 표시를 붙이지 않는다. 모든 웨이브에 같은 규칙을 쓴다.
- 잔상은 화면 전용이며 저장하지 않는다. 포커스 이탈·앱 중단 때 지우고, 수동 일시정지·선택창에서는 수명을 멈춘다. 처치 시점·보상·타깃·웨이브 전환·모델·RNG·저장 형식·HP·배속·영입 규칙은 바꾸지 않았다. 적이 더 오래 살아 있거나 초반 인지 문제가 해결됐다는 의미가 아니다.
- 네이티브 창 제목은 동결한 프로젝트 설정의 v0.9를 유지한다. 전달물·배포 wrapper의 릴리스 식별은 v0.10이다.

- v0.9는 1·2·3·5·10배속과 첫 영입부터 3영웅 각각 1/3 무작위 뽑기를 적용했다. 처음 두 번 미보유 영웅 보장은 폐지됐다. 첫 중복 즉시 승급·2갈래 선택과 이후 중복 성장은 유지한다. [v0.9 확정 보충](proposals/2026-10-03_v09-canonical-speed-recruitment-addendum.md)이 이전 보장 규칙을 명시적으로 대체한다.
- 기존 결과·RNG 상태·열린 선택창은 그대로 복원하며 다시 뽑지 않는다. 기존 런의 향후 영입도 새 전체 명단 규칙을 사용한다. 가격 12·12·24·이후 +6, XP·고철·스폰 타이밍·명단·카드 수치는 변경하지 않았다.
- 60Hz 고정 스텝을 유지하며 250ms 실제 시간 제한 후 배속을 적용한다. 모달·종료는 즉시 멈추고 선택 후 밀린 시간을 몰아서 처리하지 않는다.
- v0.8의 새 런은 1~9웨이브 스폰 구간을 28초에서 32초로 늘리고 10웨이브는 28초를 유지한다. 기존 런은 남은 런 전체에서 이전 28초 타이밍을 유지한다. 전투 중·선택창 복원과 백업 복구에도 같은 런 규칙을 적용한다.
- 적 수·HP·경제·영웅·카드 수치는 그대로다. 기존 표준 정책 시뮬레이션의 빈 대기 중앙값 약 89→57초는 제한된 관측이며, 적 조기 소멸 문제나 사람의 재미·난이도를 해결했다는 뜻은 아니다.
- v0.7은 3영웅 텍스처의 import 크기 제한과 축별 UV 보정을 통합했다. 원본 PNG·메시·메타데이터·발/총구 기준점은 보존했으며 런타임 소스 변경은 4개 파일에 한정된다.
- v0.7 당시 PCK는 v0.6 대비 4,007,088 bytes, 38.46% 작아졌다. 세 영웅의 디코딩된 mip 이미지 할당량은 25,154,992 → 3,959,012 bytes로 84.26% 감소했다. 전체 GPU·프로세스 메모리 절감률, FPS 개선률 또는 휴대폰 성능 보장이 아니다.
- v0.6의 적 HP·장갑·보스 전면 표시, 출입구 가독성, 실제 HP 손실량 기반 누수 피드백과 마지막 적 누수 뒤 웨이브 전환 보호를 유지한다.
- v0.5의 비비·탄코·로코 원화, 발사 사건 기반 단일 스프라이트 메시 모션, 전장 안으로 자른 배치 사거리와 전면 승급 배지를 유지한다. 완전한 관절 리그는 아니다.
- v0.4의 같은 런 이어하기·저장 schema·백업 복구·손상 보존·새 런 확인/취소 보호를 유지한다. 기존 런을 강제로 초기화하지 않는다.
- 효과음·BGM, 반응형·터치·동작 줄이기, DPR·포인터 대응을 보존한다. 신규 음향 설정 기본값은 OFF다.
- v0.1·v0.2·v0.3·v0.3.1·v0.4·v0.5·v0.6·v0.7·v0.8·v0.9의 열 런타임 버전과 기존 저장 브리지를 보존했다. 엔진과 저장 경로는 바꾸지 않았다.
- [v0.3 게임 규칙](proposals/2026-10-03_v03-canonical-decisions.md)의 영웅·중복·갈래·카드·경제 방향을 유지한다. 초기 미보유 보장은 v0.9 보충으로 대체됐다. 과거 보고의 미배포·계획 문구는 당시 상태이며, 현재 구현은 이 문서와 [v0.10 보고](proposals/2026-10-03_main-v10-release-integration-report.md)를 따른다.

## 이어하기와 이전 버전 주의

현재 런은 v0.10에서 이어한다. 이번 잔상 변경은 v0.9 대비 저장 호환 경계를 추가하지 않는다. 2배를 넘는 저장 속도는 v0.8 이하 클라이언트가 읽지 못할 수 있다. v0.8 전환 때부터의 아래 이전 클라이언트 복구 경계도 여전히 주의한다. 기존 런은 기존 타이밍으로 이어진다. v0.7을 단순히 여는 것은 읽기 전용이며 저장을 변경하지 않는다. 다만 새 런 전환이 중단되어 새 저장과 이전 호환 저장이 함께 남으면 v0.7의 복구는 더 이른 진행을 제시할 수 있다. 이를 명시적으로 이어하면 활성 저장이 옛 진행으로 교체될 수 있고, 먼저 보존된 새 저장 바이트가 자동으로 돌아오지는 않는다. 정상 완료된 새 v0.8 런은 v0.7에서 이어하기가 비활성화된다.

## 검수 경계와 다음 인수

최종 소스와 정확한 최종 PCK에서 각각 21개 검수 묶음이 통과했다. 상속 회귀 19개와 새 잔상 수명·128사례 전 화면 비교를 포함한다. 최종 포커스 보완 이전에 시작했던 소스 회귀 기록은 그대로 두고, 최종 코드에서 19개를 깨끗하게 다시 실행해 모두 exit 0임을 확인했다. 최종 PCK의 포커스/중단 추가 4사례도 통과했다.

동일한 128사례의 소스/PCK 전 화면 비교에서 각각 324,840항목으로 모델·UI·RNG·저장 캡처가 매 표시 스텝 같음을 확인했다. 기준/후보 모두 123/128승이며 기존 패배 5건도 동일하다. 자연 진행의 최대 잔상은 7개였다. 같은 사례의 소스/PCK 반복을 서로 다른 자연 플레이로 합산하지 않는다. 320/390px·1/10배속과 후반 7웨이브의 네이티브 비교 이미지 20개도 소스/PCK 간 바이트가 같았다. 두리가 화면을 관찰했으나 사람의 플레이나 실제 휴대폰 검수는 아니다.

PCK 장기 비교는 초기 360초 제한에서 80사례 뒤 시간 초과했고 원본 기록을 보존했다. 같은 PCK를 1,200초 제한으로 다시 실행해 128사례를 마쳤다. 검증 이력·독립 검수와 최종 소스 재실행 근거는 v0.10 보고에 구분한다.

**v0.10 브라우저 WASM·IndexedDB·실제 휴대폰·사람의 인지/재미·주관적 믹스는 미검증이다.** 승인된 실행 접근·기기 증거가 없는 항목은 차단/미검증 상태다. 배포 성공·네이티브 PASS·백업 바이트 일치를 웹/휴대폰 합격으로 바꾸어 쓰지 않는다. Android APK·PWA·safe-area·발열·배터리·장시간 성능도 미검증이다.
