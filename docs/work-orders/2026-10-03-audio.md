## AU-01 기존 음원 인수와 청취 검수

우선순위 1 / 상태 PENDING

[P0 제작 보고](../proposals/2026-10-02_audio-team-p0-production-v2.md)는 WAV 17개를, [전체 인계 v5](../proposals/2026-10-02_audio-team-expansion-complete-handoff-v5.md)는 기존 P0·P1·BGM과 확장 소재를 보고한다. 먼저 실제 파일을 찾는다. 이미 있는 음원을 다시 제작해서 파일 수를 늘리지 않는다.

할 일:
1. Nightroad_Audio_P0_v1.zip 또는 Nightroad_Audio_All_v1.zip의 실제 접근 가능한 파일과 manifest를 확인한다.
2. 기본 전투 P0 17개를 재읽어 형식, 채널, 샘플레이트, 길이, 샘플 피크, 비무음 여부와 해시를 검사한다.
3. 각 파일을 직접 듣고 기관총·대포·로켓 발사/착탄의 구분, 끝의 클릭, 피로한 고음, 누수 경고 식별을 기록한다. 들을 수 없으면 청취 미검증으로 남긴다.
4. 기존 P1의 UI·영입 소리와 v5의 승급 소리를 같은 방식으로 확인한다. P0 17개 안에 이 소리들이 모두 있다고 가정하지 않는다.
5. BGM이나 반복음을 사용할 후보가 있다면 반복 경계, 길이와 loop 구간을 검사한다. 단발 파일을 임의로 반복음으로 취급하지 않는다.
6. 원본 출처와 사용 조건을 확인한다. 자체 합성 보고만으로 법적 권리 심사를 보증하지 않는다.

산출물:
- 실제 파일별 인수·파일검사·청취 상태 목록
- 직접 확인한 peak·길이·포맷·해시·출처·사용 조건
- 재사용 가능, 보정 필요, 현재 미사용 구분
- 새 결과 문서: `audio_AU-01_existing-assets-audit`

완료 증거:
- 실제 파일과 문서의 보고를 대조했다.
- P0 17개 및 확인한 UI·영입·승급 파일의 직접 검사/청취 범위가 명확하다.
- 파일이 없거나 청취할 수 없으면 해당 부분은 BLOCKED 또는 미검증이며, 제작 보고를 검수 결과로 대신하지 않았다.

## AU-02 현재 3영웅 이벤트 인계표

우선순위 2 / 상태 PENDING / AU-01 이후

현재에는 수동 궁극기가 없다. 기존 궁극기 음원은 삭제하지 않고 현재 비활성 소재로 남긴다. 중복 재료 누적·최대성 환급 소리도 현재 정상 이벤트로 연결하지 않는다.

인계할 이벤트:
- 기관총 실제 발사
- 대포 발사와 실제 착탄
- 로켓 발사와 실제 착탄
- 소이·관통 등 실제 구현된 갈래 효과
- UI 확인·거절·보조 카드 선택
- 신규 영입
- 첫 중복 승급과 갈래 확정
- 이후 중복 승급
- 적 처치·누수·보스 조우·결과 중 실제 존재하는 이벤트

할 일:
- 기존 파일을 먼저 재사용하고 이벤트별 sound ID, 상대 파일 경로, gain, 동시 재생 수, 최소 간격, 우선순위, loop 여부와 해시를 정리한다.
- 갈래·음향 이벤트의 실제 API를 모르면 “의미 기준 제안 매핑”으로 표시하고 두리에게 연결 지점을 요청한다.
- 영입 거래 1회에 중복 영입음·재료음·승급음이 겹치지 않도록 단일 사건 정책을 제안한다.
- 카드 선택·정지·새 런·결과 전환 뒤 늦은 소리가 몰려 재생되지 않도록 정리 조건을 적는다.
- 개별 파일 피크와 전체 믹스 클리핑을 구분한다. gain·voice 제한은 시험 제안이며 코드 반영 완료라고 하지 않는다.
- 실제로 없는 소리가 필수라면 누락 이유와 최소 제작량을 제안한다. 승인을 받지 않은 확장 음원을 계속 제작하지 않는다.

완료 증거:
- 두리가 바로 연결할 수 있는 현재 이벤트와 파일 대응 manifest가 있다.
- 3영웅·6갈래와 현재 성장 흐름에 맞지 않는 소재는 비활성으로 표시한다.
- 파일을 승인된 경로로 인계하고 실제 파일 접근을 확인한다.
- 게임 통합·휴대폰 출력·7분 믹스 청취를 하지 않았다면 미검증으로 남긴다.

## 종료와 공개 범위

새 날짜별 audio 결과 문서에 작업 ID·상태·산출물·검수·남은 일을 적고 커밋 링크를 보고한다. 기존 음원·다른 팀 문서·게임 코드는 덮어쓰지 않는다.

공개 저장소에는 공개 승인과 사용 권리가 확인된 에셋만 업로드한다. 불분명하면 공개 문서에는 파일명·해시·검수 상태만 기록하고 실제 파일은 승인된 전달 경로로 제공한다. 배정 작업이 끝나면 기존 음원 재제작 대신 유용한 다음 후보 1~3개를 먼저 제안한다. 사용자가 그 목록 뒤 ‘ㄱ’, ‘ㄱㄱ’ 또는 ‘다음’이라고 하면 첫 후보 1개를 승인 범위 안에서 시작한다.

## 여섯 팀 협업과 의견 보고

2026-10-03 갱신: [공통 협업 규약](2026-10-03-collaboration-protocol.md)을 함께 따른다. 이 절차가 기존의 단순 “한 작업 후 대기” 안내를 대체한다. 권한·인증·파일 소유의 경계는 유지한다.

- 시작한 승인 작업은 조사·제작·검증·저장·보고까지 진행한다. 사용자가 한정된 배정 묶음을 요청했다면 그 범위를 이어가며, 평범한 단계마다 재확인을 요구하지 않는다.
- 막힌 항목을 기록하고 같은 승인 범위의 독립 작업은 진행한다. 이미 있는 결과와 체크포인트를 재사용하며 새로 시작하지 않는다.
- 결과 끝에 **문제점 / 개선 제안 / 다른 팀 요청 / 다음 작업 후보 1~3개**를 넣는다. 근거·이유·예상 효과·작업량·위험·의존성·현재 규칙과의 충돌을 적고, 다음 후보에는 우선순위와 예상 산출물을 적는다.
- 의견은 제안으로 남긴다. 두리가 채택·보류·사용자 결정 필요를 검토하고 최종 앱을 통합한다.
- 지시서가 없거나 배정이 끝났으면 가장 권장하는 다음 후보를 첫 번째로 제안한다. 사용자가 그 목록을 본 뒤 “ㄱ”, “ㄱㄱ” 또는 “다음”이라고 하면 첫 번째 후보 1개를 시작한다. 새 작업 ID와 승인 범위를 기록한다.
- 후보 승인도 중요한 규칙 변경, 다른 팀 파일 소유, 운영 코드 인계, 새 권한을 자동 허용하지 않는다. 자료 접근 실패를 지시서가 없다는 뜻으로 해석하지 않는다.
