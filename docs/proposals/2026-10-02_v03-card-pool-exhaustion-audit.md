## 1. 발견한 구체적인 문제
12종 제안은 영웅1명일 때 전용 피해/공속/사거리 3종만 활성이고 상한은5/5/3이다.
사거리 카드를3번 선택하면4번째 화면에 피해/공속2종만 남는다.
총 획득 가능 횟수13이 충분해 보이더라도 매 화면의 서로 다른3종 확보와는 다르다.
따라서 지난 제안은 현재 상태로 적용 가능한 완성된 카드 풀로 인계하지 않는다.

## 2. 가장 작은 수정 후보
12종 제안의 공용 카드 최소인원 조건을2명→1명으로 바꾼다.
효과·ID·상한은 그대로 유지한다. 새 카드·무료 영웅·무료 재추첨·갈래 지급을 추가하지 않는다.
한 영웅일 때도 공용 피해/공속/사거리는 실제 효과가 있다. 다만 전용보다 효과가 작고 이후 합류 영웅까지 적용되는 투자다.
이는 다른24안의 공용 카드3종을 더 넣자는 뜻이 아니다.
동일 효과끼리 공용이 초기에는 약하게 느껴질 수 있으므로, 이 해법은 선택지 수를 해결하는 후보이지 재미 검증 완료가 아니다.

## 3. 검산 방법과 결과
유효 조건을 소유 여부와 카드 상한으로만 제한한 모델이다. 최소 공격간격·사거리 기술 상한·기타 무효 조건은 포함하지 않았다.
각 카드 획득 수0~상한의 모든 조합 중 총 선택 횟수0~12를 열거했다. 실행 경로 수나 게임 플레이 횟수가 아니라 카드 보유 상태 수다.
유효ID3개 이상일 때 비복원 추첨이면 임의의3개 부분집합이 나올 수 있으므로, 더 적은 후보로 진행한 가상 상태까지 포함하는 검산은 안전한 상한 분석이다. 아래 최초 실패 증인은 실패 전까지3개 이상을 유지한다.

| 모델 | 카드 수 | 열거 상태 수 | 첫 후보 부족 가능 화면 |
|---|---:|---:|---:|
| 기존 혼자·공용 잠금 |3|143|4번째|
| 수정 혼자·공용 허용 |6|6,185|13번째|
| 수정 영웅2명 |9|160,606|26번째|
| 수정 영웅3명 |12|1,867,523|39번째|

2·3명 모델의26/39번째는12회 이후를 열거한 결과가 아니라 아래 정렬 공식으로 산출했다.
수정 혼자 모델의 화면1~13 직전 최소 후보 수:
6,6,6,5,5,5,4,4,4,3,3,3,2.
수정 혼자 모델에서 사거리 전용3 + 공용3종 각각3을 선택하면12회 사용 후13번째에 전용 피해/공속2종만 남는다.
그러므로 “모든 런에서 영원히3택1 보장”이라고 표현할 수 없다.

### 정렬 공식
유효 카드 N종에 양의 정수 상한 c가 있고 상한 외 제외 조건이 없다면, 후보가2개 남으려면 최소N-2종을 소진해야 한다.
가장 작은 상한 N-2개의 합을 S라 하면 최초 부족 가능 화면은 S+1이다.
- 수정 혼자: [3,3,3,3,5,5] → 가장 작은4개 합12 →13번째.
- 수정2명: 상한3 다섯 개,5 네 개 → 가장 작은7개 합25 →26번째.
- 수정3명: 상한3 여섯 개,5 여섯 개 → 가장 작은10개 합38 →39번째.
최대 강화 선택 횟수 L이 S 이하라면 해당 고정 풀에서 상한만으로는 후보 부족이 생기지 않는다.
영입으로 카드가 추가되는 현재3영웅 모델에서는 기존 효과가 계속 유효한 한 혼자 조건이 보수적인 기준이다.

## 4. 채택 조건과 남은 결정
1. 실제 v0.3 최대 강화 선택 횟수를 XP·생성·보상 데이터로 계산한다. 구안의9회를 현재 값으로 가정하지 않는다.
2. L≤12이고 실제 추가 무효 조건이 없으면 이 수정안은 영입을 전혀 하지 않아도 후보 수 조건을 충족한다.
3. L>12이면 미충족이다. 전체 카드 풀과 상한을 다시 설계하며 이 문서로 선택 횟수를 강제로12로 제한하지 않는다.
4. 공속 제한 등으로 카드가 조기에 무효가 되면 그 조건을 넣어 다시 검산한다.
5. 실제 기존 카드 풀이 이미 정상이라면 새12종으로 바꿀 필요가 없다. 현재 풀에도 동일 검산법만 적용한다.
6. 상한을 늘릴 때 총 화력을 함께 비교한다. 후보 수 확보만을 위해 +50% 상한을 무작정 올리지 않는다.
후보 부족 화면에서2장만 표시·가짜3장·무효 회복·고철 대체 등은 확정3택1 방향을 몰래 변경하므로 채택하지 않는다.

| 항목 |12종 제안|24 공용 제안|이번 처리|

두안의 역할을 합친 새로운 세번째 대규모 카드 풀은 이번에 만들지 않는다.

## 6. 재현용 순수 JavaScript
이 코드는 카드 보유 상태를 계산한 분석 예제이며 게임 패치가 아니다.
```js
function audit(caps, limit=12) {
  let states=0;
  const minimum=Array(limit+1).fill(Infinity);
  function visit(i, used, available) {
    if (used>limit) return;
    if (i===caps.length) {
      states++;
      minimum[used]=Math.min(minimum[used], available);
      return;
    }
    for(let level=0;level<=caps[i];level++)
      visit(i+1,used+level,available+(level<caps[i]?1:0));
  }
  visit(0,0,0);
  const firstShortage=1+[...caps].sort((a,b)=>a-b)
    .slice(0,caps.length-2).reduce((a,b)=>a+b,0);
  return {states,minimum,firstShortage};
}
console.log(audit([5,5,3]));
console.log(audit([5,5,3,3,3,3]));
console.log(audit([5,5,3,5,5,3,3,3,3]));
console.log(audit([5,5,3,5,5,3,5,5,3,3,3,3]));
```
