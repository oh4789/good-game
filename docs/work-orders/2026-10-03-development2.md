우선순위 1 / 상태 PENDING

두리가 v0.4 이어하기·저장 보호·음향 연결을 진행 중이다. 이 파일들을 개발2가 동시에 수정하지 않는다. 먼저 안정 v0.3을 기준으로 재현 가능한 UI 관측과 낮은 위험의 검수 도구를 준비한다.

### 소스와 실행 접근 확인

1. 같은 사용자에게 승인된 Library 또는 첨부에서 `Nightroad-Square-Defense-v0.3-SOURCE.zip`을 찾고 실제 파일을 연다.
2. 기대 소스 `922f0808783aa31a88395a80c877e71bce7f0edc`, ZIP 해시, 내부 버전 기록과 실행법을 대조한다.
3. 공개 GitHub는 현재 문서 자료실이다. 소스가 없으면 정확한 파일명·기대 버전과 필요한 첨부를 요청하고 BLOCKED로 기록한다.
4. 비공개 Site 접근은 별도다. 소스 검수 환경이 실행되더라도 배포 Site 로그인·WASM·브라우저 저장을 통과한 것으로 계산하지 않는다.
5. 기존 QA의 로그인 차단은 이미 알려져 있다. 같은 인증 요청을 반복하거나 공개 전환을 요구하지 않는다.

### 격리 작업 범위

- 인수한 소스의 별도 사본을 사용한다. Git 작업이면 로컬 격리 브랜치 `work/dev2-v03-ui-audit-20261003`를 쓴다.
- 이번 쓰기 허용 범위는 그 사본의 새 전용 경로 `workbench/dev2/DV2-01/` 안의 검수 도구·입력·스크린샷·보고다.
- 기존 UI, 저장, 이어하기, 음향과 공용 상태 파일은 수정하지 않는다.
- 실제 UI 경로와 신호를 읽어서 사용한다. 문서만 보고 가상의 셀렉터·파일·API를 만들어 구현 완료로 보고하지 않는다.
- 기존 파일 수정이 필요한 결함은 실제 경로·줄·최소 diff 제안으로 정리한다. 제안은 별도 전달물이며 운영 소스에 적용하지 않는다.
- 코드·패치는 승인된 비공개 경로로 두리에게 인계한다. 이 공개 저장소에 자동으로 올리지 않는다.

### 검수할 내용

- 지원되는 로컬 실행 환경에서 시작, 영입, 첫 중복 2갈래, 보조 카드, 결과, 새 런의 화면과 입력을 확인한다.
- 좁은 세로·가로 화면에서 실제 크기, 텍스트 잘림, 핵심 버튼 접근, 터치 표적 크기와 키보드 포커스를 기록한다.
- 데스크톱 뷰포트 축소와 실제 휴대폰 검수를 구분한다. 운영체제·브라우저·기기별로 실행한 범위만 적는다.
- 선택 창의 입력 관통, 두 번 입력, 닫기·뒤로 가기·새 런 이후 남는 상태를 기존 지원 동작 안에서 확인한다.
- 궁극기, 3성 MAX, 중복 재료와 옛 카드 갈래 안내가 실제 화면에 남아 있는지 관측한다. 존재를 추정해서 삭제하지 않는다.
- 접근성 트리·화면·엔진 테스트 중 사용할 수 있는 증거를 남긴다. 캔버스가 텍스트를 노출하지 않으면 그 한계를 명시한다.
- 저장은 v0.3의 최고 웨이브 동작만 관측한다. 중간 런 이어하기 미지원은 v0.3 결함으로 표시하지 않는다. 개발 중인 v0.4 저장 로직은 인계 전 건드리지 않는다.

### 산출물과 완료 조건

- 실제 소스와 UI에 연결되는 전용 테스트 하네스 또는 재현 스크립트
- 기준 버전·실제 코드 경로·변경 경로 목록·실행 명령
- 화면 크기별 결과와 직접 확인한 스크린샷
- 통과·실패·미검증 목록
- 문제가 있으면 영향·재현·최소 diff 제안·회귀 검수 항목
- 새 결과 문서 `development2_DV2-01_v03-ui-audit`

실행할 수 없는 환경이면 정적 소스 검토와 실행 검수를 구분한다. 스크립트 문법 검사만으로 UI 통과를 선언하지 않는다. 읽을 소스가 없으면 경로나 패치를 상상하지 않고 차단 보고로 마친다.
