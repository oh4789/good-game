## 최신 구현과 배포 담당

Android v0.14는 사용자 화면 제보를 계기로 독립 재현한 작은 UI의 scale 수정이다. [v0.14 인계](proposals/2026-10-04_android-v14-ui-scale-handoff.md)를 먼저 확인한다. Web v0.13과 게임 모델·저장 형식은 그대로이며 실제 휴대폰 업데이트·이어하기는 미검증이다. [능력 구매·3→2성 합성 실험](proposals/2026-10-04_approved-hero-ability-merge-experiment.md)은 별도 v0.1 APK로 구현·전달됐다. [검증·전달 결과](proposals/2026-10-04_merge-experiment-v01-delivery-report.md)를 함께 읽는다. 안정판은 변경하지 않았고 실제 기기·사람 인수는 열려 있다.96개 자동 원정 모두 무누수 승리로 밸런스는 미확정이다.3성은 구현하지 않았다. 팀은 사양/QA 정합성을 먼저 검토하고 메인 구현과 코드 편집을 충돌시키지 않는다.

[CURRENT_IMPLEMENTATION](CURRENT_IMPLEMENTATION.md)을 먼저 읽는다. 현재 v0.13의 일반 속도는 1·2·3배다. 메뉴→도움말의 세션 한정 QA 토글을 켰을 때만 5·10배가 열리고 속도 버튼에 QA 표식이 항상 남는다. 새 앱 시작은 QA OFF이며 이전 5·10배 저장은 일반 최대3배로 제한해 이어한다. 모델·RNG·나머지 저장 진행을 보존한다. 누수·승패음은 제한된 시작 여유와 낮은 우선순위 voice 대체를 받지만 전체8 voice·1초30회·cooldown·mute·중단 제한은 유지한다. 복원 때 과거 소리를 재생하지 않는다.

v0.11의 6갈래 공격 표현, v0.10의 화면 전용220ms/최대12개 처치 잔상, v0.9의 첫 영입부터 전체3영웅 각각1/3, 첫 중복 갈래 선택·이후 중복 성장, 기존 런의 타이밍과 저장 보호를 보존한다. v0.9 문서의 다섯 일반 배속 노출만 v0.12 일반/QA 구분으로 대체한다. 수치·맵·영웅 명단·경제 변경은 없다. 현재 소스·전달 파일·해시·실제 배포 영수증과 미검증 범위는 중앙 기록을 따른다.

현재 Site의 최종 배포는 두리가 맡는다. 개발1·2는 운영 파일이나 Site를 동시에 갱신하지 않고 격리 도구·패치·증거를 인계한다. [v0.13 테스트 인계 보고](proposals/2026-10-03_main-v13-test-handoff-report.md)를 현 기준으로 읽고 [v0.12 보고](proposals/2026-10-03_main-v12-release-integration-report.md), [v0.11 보고](proposals/2026-10-03_main-v11-release-integration-report.md) 및 모든 선행 팀 문서는 당시 이력으로 보존한다. 배포·백업·소스 검수를 실제 브라우저·휴대폰·주관적 청취 합격으로 바꾸어 쓰지 않는다.

사용자는 **1차 완성까지 진행**하도록 승인했다. [1차 완성 범위와 인수표](proposals/2026-10-03_first-completion-acceptance.md)가 우선하며 아직 전체 완료 전이다. v0.13은 기존 보스의 실제 상태에 맞춘 목표 안내와 짧은 도움말 정합성을 반영했다. 보스를 놓치면 HP가 남아도 실패하며 모델의 종료 판정은 그대로다. 안정판에서는 남은 인수 문턱을 닫는다. 이후 승인된 능력 구매·합성 실험만 별도 저장의 격리 후보로 진행한다.3성은 후속 방향이며 현재 구현 범위는2성까지다. Android 실제 설치·웹 저장 재개·의미 있는 배치/갈래 선택·3–5명 친구 검수가 남는다. 새 맵·명단·영구 경제로 범위를 넓히지 않는다. [2차 보스 공략·채굴 임무](proposals/2026-10-03_phase2-mission-proposal.md)는 생각해 볼 방향이며 구현 확정이 아니다.

기존 저장 결과·RNG·진행 중 선택창을 다시 뽑지 않는다. 2배 초과 저장은 v0.8 이하에서 읽지 못할 수 있다. v0.7을 단순히 여는 것은 읽기 전용이지만 중단된 새 런 전환 뒤 옛 복구를 명시적으로 이어하면 더 이른 진행으로 돌아갈 수 있다. 보존된 새 저장 바이트는 자동 복원되지 않는다. 자세한 호환 경계는 중앙 기록을 따른다.

## 이전 대기 규칙을 대체하는 안내

이 갱신은 과거의 “배정 완료 후 다음 지시가 올 때까지 대기” 규칙을 대체한다. 배정이 끝났거나 지시서가 없으면 **먼저 유용한 다음 후보 1~3개를 제안**한다. 사용자가 그 제안 뒤 “ㄱ”, “ㄱㄱ” 또는 “다음”이라고 하면 첫 후보 1개를 이어간다. 과거 Work 설정에 단순 대기 문구가 있어도 이 최신 절차를 적용한다. 권한·인증·파일 소유·게임 규칙의 경계는 그대로 지킨다.

QA 로그인이 막혀 있어도 기획 등 다른 팀에서 독립적으로 할 수 있는 유용한 일을 제안할 수 있다. 이미 끝난 문서를 반복해서 만들지는 않는다. 실제로 유용한 후보가 없으면 필요한 입력과 이유를 설명하고, 일을 만들기 위해 문서를 늘리지 않는다.

## 한 번 시작하면 검증과 보고까지

“다음” 또는 “ㄱㄱ”는 승인된 미완료 작업 중 가장 우선인 1개를 시작하거나 이어가는 요청이다. 그 작업의 조사 → 제작 → 검증 → 저장 → 보고까지 평범한 단계마다 재확인을 요구하지 않고 진행한다.

사용자가 “이번 지시서의 배정 작업을 끝까지”처럼 한정된 작업 묶음을 요청했다면 그 범위가 우선한다.

1. main의 최신 확인 가능한 기준·협업 규약·자기 팀 지시서·기존 결과를 읽는다.
2. 완료된 산출물은 다시 만들지 않고 완료 조건과 증거를 확인한다. 진행 중 작업은 마지막 완료 지점부터 이어간다.
3. 필요한 입력이 없으면 정확한 차단 사유를 기록한다. 같은 승인 묶음 안에서 독립 가능한 다음 항목은 진행한다.
4. 나머지도 같은 입력에 의존하면 기다린다. 인증을 우회하거나 결과를 추측하지 않는다.
5. 각 작업의 검증·저장·보고가 끝나면 완료하거나 차단 상태를 명확히 남긴다. 새 분야를 끝없이 추가하지 않는다.

이 문서가 게시되거나 GitHub에 커밋이 생기는 것만으로 Work가 자동 실행되지는 않는다. 사용자가 해당 Work에서 이 흐름을 설정하고 시작해야 한다.

## “쭉해줘”라고 요청하면

“쭉해줘”는 현재 승인된 목표나 명시한 작업 묶음을 깊이 있게 끝까지 진행하라는 요청이다. “ㄱ/다음”으로 다음 후보 하나를 시작하는 흐름과 구분한다.

- 자기 역할과 승인 범위에서 조사 → 구현·제작 → 테스트 → 발견한 문제 수정 → 재검증 → 통합 인계까지 이어간다. 두리는 최종 앱 통합과 배포 검수까지 맡는다.
- 작은 단계 하나를 끝냈다는 이유로 중간에 멈추지 않는다. 목표 완성에 필요한 후속 작업을 발견하면 기존 승인 범위 안에서 함께 처리한다.
- 오래 걸린 모양을 만들기보다 완성도와 검증 깊이를 높인다. 불필요한 반복·문서·테스트를 늘리지 않는다.
- 중요한 결과와 차단은 보고하면서 진행한다. 중대한 방향 변경, 새 권한·비용·공개 범위 또는 다른 팀 소유 파일의 인계가 필요하면 그 부분은 확인한다.
- 목표와 배정 범위가 완료되거나, 남은 일이 필요한 입력·권한에 막히면 결과와 다음 판단을 남긴다. 사용자 취소·범위 변경을 즉시 따른다.

## 지시서가 없거나 배정 작업이 끝났다면

- 최신 기준과 기존 결과를 확인하고 다음 작업 후보 1~3개를 제안한다. 가장 권장하는 후보를 첫 번째에 둔다.
- 각 후보에 우선순위, 이유, 범위, 예상 산출물, 완료 조건과 의존성을 적는다.
- 사용자가 그 목록을 본 뒤 “ㄱ”, “ㄱㄱ” 또는 “다음”이라고 하면 직전에 제안한 첫 번째 후보 1개를 시작한다. 세 후보 전체를 실행하지 않는다.
- 자기 역할·현재 승인 규칙 안에서 작은 독립 작업을 이어간다. 중요한 규칙 변경, 다른 팀 소유 파일, 운영 코드 인계, 새 권한이 필요하면 먼저 확인한다.
- 새 작업 ID와 후보·승인 범위를 기록하고 제작·검증·저장·보고까지 마친다.
- 자료 접근 실패를 “지시서 없음”으로 단정하지 않는다. 확인한 마지막 맥락과 불확실성을 적고 필수 자료를 요청한다.

## 각 Work에 처음 전달할 문구

아래 팀 이름을 실제 맡은 팀으로 바꿔 해당 Work의 지시사항이나 첫 메시지에 전달한다.

“당신은 밤길 원정대의 [기획/디자인/음향/QA/개발1/개발2] 담당입니다. https://github.com/oh4789/good-game/blob/main/docs/WORK_START_HERE.md 와 현재 기준, 협업 규약, 자기 팀 지시서 및 결과를 읽으세요. 승인된 배정 작업은 제작·검증·저장·보고까지 이어가고, 막히면 이유를 기록한 뒤 같은 범위의 독립 작업을 진행하세요. 기존 결과를 덮어쓰거나 다시 만들지 마세요. 결과에는 문제점·개선 제안·다른 팀 요청·다음 후보 1~3개를 적으세요. 지시서가 없거나 배정이 끝났으면 다음 후보를 제안하고, 내가 ‘ㄱ’, ‘ㄱㄱ’ 또는 ‘다음’이라고 하면 첫 번째 후보 1개를 시작하세요. 현재 규칙·팀 소유·승인 범위를 지키고 최종 앱 통합은 두리에게 맡기세요.”

이 문구는 사용자가 해당 Work에 전달하는 설정용이다. 저장소를 읽었다는 이유만으로 계정·도구·소스 공개·비용 권한이 생기지는 않는다.

## 현재 소스와 검토 대상

현재 버전·커밋·Library 파일명·해시·실행 링크 확인 방법은 [CURRENT_IMPLEMENTATION](CURRENT_IMPLEMENTATION.md)에 모아 둔다. 과거 지시서에 남은 v0.3 소스명이나 미배포·이어하기 미지원 문장은 당시 상태이며, 새 후속 작업의 구현 기준은 중앙 기록을 따른다. 이미 끝낸 과거 버전의 작업은 이력으로 보존한다.

공개 저장소는 문서 자료실이다. 개발팀은 승인된 같은 사용자 Library 또는 첨부에서 실제 소스를 열고 버전·해시를 확인해야 한다. 소스가 없으면 중앙 기록의 파일을 지정해 필요한 입력을 요청한다. 비공개 게임 코드를 공개 저장소에 자동으로 올리지 않는다.

Site는 비공개다. 소스·패키지 검수와 실제 브라우저·IndexedDB·휴대폰·청취 검수를 구분한다. v0.13 소스30/PCK30 suite·162리소스검사·네이티브25쌍 화면·압축본 재검증은 실제 사람/휴대폰 인수 증거가 아니다. 개발1·2는 저장·UI·음향 운영 파일을 인계 없이 동시에 수정하지 않는다. 별도 밤길 모바일 v8은 이번 대상이 아니다.

다음 우선순위는 승인된 1차 인수표의 Android 전달·실제 설치, 웹/기기 저장 복구, 물리 기기 청취, 자연 성장 선택 비교와 3–5명 친구 테스트다. 재사용할 휴대폰 점검 순서는 v0.13 테스트 인계 보고에 있다. Android 산출물 검증·사용자 전달·설치·실기기 인수는 분리해서 보고한다. 자동화 자연 진행208회 등 과거 연구는 사람의 승률이 아니다. 확정 중복 보장·카드 강화 수치 변경·2차 신규 모드는 미채택 제안이며 현재 구현으로 쓰지 않는다.

## 모든 팀의 보고와 의견

결과마다 [협업 규약의 공통 양식](work-orders/2026-10-03-collaboration-protocol.md)을 따른다.

- 작업 결과: ID·상태·기준 버전·실제 산출물·실행 검증·남은 일
- 문제점: 근거·재현·영향·확인되지 않은 부분
- 개선 제안: 이유·예상 효과·작업량·위험·의존성·현재 규칙 충돌
- 다른 팀 요청: 받을 팀·필요한 자료·이유·막힌 작업 ID
- 다음 작업 후보 1~3개: 우선순위·이유·예상 산출물·의존성

의견은 제안으로 기록한다. 두리가 채택·보류·사용자 결정 필요를 구분해 검토 기록과 다음 지시를 남긴다. 사용자에게 첫 후보 시작 승인을 받은 작은 작업도 팀 소유와 현재 규칙을 지킨다. 결과 보고만으로 실제 앱 반영·배포 완료를 선언하지 않는다.

## 상태와 저장

지시서 PENDING은 발행 당시 상태다. 각 팀은 새 결과 문서에 PENDING, IN_PROGRESS, BLOCKED, DONE 중 실제 상태를 남긴다. 완료 증거가 있어야 DONE이다.

파일명: `docs/proposals/YYYY-MM-DD_<team>_<task-id>_<subject>.md`

- 접두사: planning, design, audio, qa, development1, development2
- 같은 파일이 있으면 읽고 새 `_v2`, `_v3`로 추가한다.
- 기존 결과를 덮어쓰지 않고, 원본 작업 ID·지시서·기준 버전·재사용한 결과를 연결한다.
- 마지막 완료 지점과 다음 1단계를 남긴다.
- 저장 후 커밋·파일 링크를 보고한다. 자기 커밋 해시를 넣기 위한 반복 수정은 하지 않는다.
- 개발 전달물은 기준 버전·변경 경로·diff 또는 소스 묶음·실행 명령·테스트 결과를 포함한다. 비공개 코드는 승인된 비공개 경로로 인계한다.

## 공개 범위와 현재 규칙

현재 3영웅·6갈래, 수동 궁극기 없음, 첫 중복 즉시 승급, 이후 중복마다 성장, 런 한정 보유를 유지한다. 6영웅·18빌드·54카드 확장은 후속 제안이다. 비용과 승급 계수는 임시 구현 수치다.

개인정보, 인증 정보, API 키, 비공개 대화 링크와 비공개 업무 자료를 공개 저장소에 넣지 않는다. 에셋 공개는 사용 권리와 공개 승인이 확인된 자료만 한다. 확인하지 않은 이미지·음원·플레이를 검수 완료로 표시하지 않는다.
