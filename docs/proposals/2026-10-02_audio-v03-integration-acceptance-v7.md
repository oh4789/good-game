## 확인한 사실
Sites 조회에서 사각 방어전 최신 저장 버전은 3, 소스 커밋은 11a9a0a43af37888e6489167e8fb1fc7173fb0f1이다. 현재 live URL은 https://nightroad-square-defense.oh4789.chatgpt.site 이다.
버전3 보관 묶음은 38,584,320바이트, 44파일로 보고된다. 다운로드 도구는 "file could not be authorized or resolved"를 반환했다. 원인을 파일 크기로 단정하지 않는다.
따라서 소스의 실제 사건 이름, AudioStreamPlayer, 버스, 음원 포함 여부를 읽거나 검증하지 못했다. 연결됨/미연결 어느 쪽으로도 결론 내리지 않는다. 브라우저 청취와 휴대폰 검수도 수행하지 않았다.
현재 음원은 Nightroad_Audio_v03.zip의 32개 변형/24개 ID를 유지한다. 새 음원 제작이나 게임 코드 수정·배포는 이번 작업에 없다.

## 확정 규칙과 제안 구분
현행 기준 문서가 보고한 사용자 확정: 자동 전투, 첫 중복 즉시 승급 및 2갈래 선택, 추가 중복 계속 승급, 보조 카드와 승급 분리.
아래 표는 음향 연결 제안이다. event_map.json의 키는 의미상 사건이며 실제 엔진 API가 아니다.

## 성장·UI 연결 제안
| 유효 사건 | 사용 ID | 중복 방지 |
|---|---|---|
| 새 영웅 영입 완료 | ui_recruit_new | generic confirm을 추가하지 않음 |
| 첫 중복 승급 완료 및 갈래 창 표시 | ui_promote | 같은 흐름의 ui_branch_open 생략 |
| 추가 중복 승급 완료 | ui_promote | 중복 영입음·재료음 없음 |
| 갈래 선택 승인 | ui_branch_apply | 버튼 입력 시점이 아닌 승인 시점, generic confirm 생략 |
| 카드 창 새로 열림 | ui_level_open | 재렌더/복귀 시 반복하지 않음 |
| 카드 선택 승인 | ui_card_apply | 승급음과 구분, generic confirm 생략 |

ui_branch_open은 독립적인 창 열림 표현에 쓸 수 있는 보유 자산이며, 반드시 재생해야 하는 사건이 아니다.
승급과 카드가 겹칠 때의 논리적 처리 순서는 개발팀의 확정 정책을 따른다. 소리 때문에 게임 상태 변경을 늦추지 않는다.

## 6갈래 연결 제안
| 갈래 | 우선 재사용 | 개발 연결 시 확인 |
|---|---|---|
| BBI 연사 | sfx_mg_fire | 실제 발사 사건 기반, 재생 제한은 피해 판정과 분리 |
| BBI 탄막 | sfx_mg_fire | 동시 탄환 수만큼 음량이 누적되지 않도록 묶음/동시수 정책 필요 |
| CAN 폭발 | sfx_cannon_fire, sfx_cannon_impact | 착탄 1건과 범위 내 적별 피해를 구별 |
| CAN 소이 | sfx_cannon_fire, sfx_cannon_incendiary_ignite/loop | 장판 생성·활성 수명에 연결, 피해 틱마다 점화음 재생 금지 |
| RKT 유도 | sfx_rocket_fire, sfx_rocket_impact | 실제 종결 착탄 사건 확인 후 연결 |
| RKT 관통 | sfx_rocket_fire, sfx_enemy_hit | 관통 접촉마다 폭발음을 연결하지 않음; 종결 충돌 표현은 실제 판정 확인 후 결정 |

현재 event_map의 projectile_impacted:RKT → sfx_rocket_impact는 갈래 조건이 없는 의미상 초안이다. 그대로 모든 관통 접촉에 적용하면 최신 제작 지시의 관통/폭발 구별과 충돌할 수 있다. 실제 충돌 종류를 확인해 조건을 좁힌 뒤 연결한다.
6갈래별 새로운 고유 음색이 모두 제작됐다는 뜻은 아니다. 현재 자산 재사용과 재생 타이밍으로 먼저 검수한다.

## 전투·상태 인수 기준
- 처치: enemy_killed에 사망음. 살아남은 피격과 사망음을 한 피해 사건에 무조건 중첩하지 않는다.
- 누수: enemy_leaked에 sfx_leak. 사망음·처치 보상 사건과 분리한다. 누수 소리를 합치더라도 실제 HP 손실과 수량을 보존한다.
- 소이 루프: 활성 장판이 0에서 양수로 바뀔 때 시작, 양수 유지 중 추가 루프 중복 생성 금지, 0이면 종료. 제안상 공용 루프 하나를 사용한다.
- 준비/카드: 문서19의 BGM -6 dB는 상대 감쇠 제안이며 원본 파일 보정과 중복 적용하지 않는다.
- 수동 정지/숨김: 기존 재생 위치에서 정지·재개. 정지 사유가 남아 있으면 재개하지 않는다.
- 새 런/종료: 이전 런의 지연 콜백과 소이 루프 정리. 결과음 1회. BGM 300ms fade는 문서19 제안값.
- 중복 제거 키는 runId+eventId 등 실제 개발 인터페이스 확정 후 사용. 동일 이벤트 재수신·UI 재렌더·복귀를 새 사건으로 취급하지 않는다.

## 개발 적용 후 필요한 최소 증거
동일 빌드에서 영입→첫승급→갈래확정→추가승급→카드, 처치/누수, 소이 장판 중첩/종료, 관통 다중 적중을 기록한다.
각 기록에 실제 사건 이름·발생 횟수·재생 ID·재생 횟수를 붙인다. 음원 경로, 버스명, 실행 커밋도 함께 확인한다.
별도 밸런스 40런을 다시 요구하지 않는다. 기존 60초 오프라인 믹스는 이 런타임 검수의 대체물이 아니다.
음향 인수 완료 표시는 실제 적용 빌드와 청취 증거가 확보된 뒤에만 한다.
