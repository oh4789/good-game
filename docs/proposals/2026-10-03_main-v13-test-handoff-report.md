## 반영 범위

동결 v0.12 소스 `96711a6e67033a8040311843a76db1e0072b1d00`에서 v0.13 소스 `943787fe1a72051b494a5f2bd97fd9b8d35366c0`로 진행했다. 런타임 변경은 `scripts/SquareScreen.gd` 하나다. 모델·RNG·피해·성장·맵·적·명단·음향·에셋·저장 형식·일반/QA 배속 정책은 그대로다.

- 기존 상태 줄에 최종 웨이브 준비 목표, 보스 등장 대기, 실제 살아 있는 보스의 HP, 보스 처치 후 잔여 적 정리, 미처치/결과 대기 상태를 보여준다. 전투 일시정지 표기도 상태를 따른다.
- HP는 실제 보스 Dictionary에서 읽어 정수 올림으로 표시한다. 화면이 새 보스·타이머·공격이나 별도의 승리 판정을 만들지 않는다.
- 최종 보스를 놓치면 HP가 남아도 원정 실패다. 기존 누수 피해20을 버티는 것만으로 클리어하지 않는다. 종료 시점과 승패 결정은 기존 모델이 맡는다.
- 도움말 맨 앞에 짧은 조작과 목표를 두고 낡은 버전/임시 아트 문구를 제거했다. 신규 영웅과 첫 중복의 갈래 선택, 이후 중복 성장, 공용 XP 카드, 일반1·2·3배와 세션 한정 QA5·10배를 구분한다.
- [PL-08 문구 검토](2026-10-03_planning_PL-08_v10-copy-delta_v2.md)의 T1–T3를 짧게 재사용했다. T4–T7 장문 확장은 보류다. 보스/조작 첫 문장은 현재 모델을 근거로 작성한 새 안내다.

## 소스·PCK·네이티브 확인

- 소스와 정확한 동결 PCK: 기존 회귀 각각30/30 suite 통과.
- ObjectiveUI: 각각888검사. 320×568, 390×740, 568×320에서 일반1/2/3배와 QA10배를 확인했다.
- 실제 모델의 최종 스폰·생존HP·처치 후 생존 적·보스가 마지막 적·양의HP에서 보스 유출 실패·누락 보스·결과/초기화 전이를 검사했다.
- 등장 직전과 살아 있는 일시정지 보스의 실제 RunStore 재로딩, 도움말 모달 복원을 검사했다. 기존 고배속 복원 시3배 제한 외에 모델/RNG/저장 내용이 달라지지 않았다.
- 두 시드×8갈래 조합의 자연 진행16쌍: 소스/PCK 각각25,632검사. 표본 상태/RNG와16개 최종 저장 JSON이 기준 버전과 바이트 동일했다. 배속은 조합에 걸쳐1/2/3/10배로 분산했다.
- 컴파일된 정확한 PCK 리소스·음향·노드 바인딩162검사 통과.
- 네이티브 X11/Mesa의 통제 화면21쌍과 자연 진행4쌍을 비교했다. 소스25개 이미지를 확인했고 정확한 PCK의25개 재렌더링 PNG가 소스와 바이트 동일했다.
- 자연 시드44217·1배속 자동 정책 한 판은 HP20·활동404.6초로 승리했다. 사람의 승률·재미·7분 목표 합격 증거로 세지 않는다.
- 새 SOURCE 압축본의 추출/재import 후 집중검사와 새 PCK 검사를 다시 수행했다. 열거한 런타임 payload111개가 바이트 동일했다. 생성 패키징 메타데이터 때문에 전체 새 PCK 바이트는 다를 수 있다.

초기 Web export는 잘못된 preset 이름과 격리 환경의 Web template 부재로 실패했다. 이후 로컬 export-pack으로 확인한 PCK를 인계했다. PCK 네이티브 harness 경로 문제는 수정 후 재검증했으며 환경의 기존 V-Sync 경고와 구분했다. 이 과정은 브라우저 실행 증거가 아니다.

## Android 시험 APK와 전달 상태

Android v0.13 시험 APK는 제작·파일 검증됐다. Nightroad-v0.13-Android-arm64-optimized-test.apk, 31,996,783 bytes, SHA256 `343a6a887384c6f27b93df3af5ccc5ad45ad1baf475972fc9df0d7538ca8bdc7`. Android7+(minSDK24), target36, ARM64-v8a만, 세로 화면, 요청 권한 없음. 패키지 org.godotengine.nightroad.test / versionCode13 / 0.13-test이며 v0.12와 같은 프로젝트 시험 서명이다. manifest는 버전 필드만 달라졌다. v2/v3 서명·16KB 정렬과 APK 리소스8개 suite(ObjectiveUI888검사·ObjectiveParity 포함)가 통과했다. 백업은 저장됐으나 이 APK의 다운로드 전달은 아직 별도 단계다. v0.12 다운로드 페이지는 앞서 소유자에게 제공됐다. 다운로드·설치·업데이트 시 저장 보존·실제 기기 플레이는 미검증이다.

APK 생성·서명/리소스 검증, 다운로드 페이지 제공, 실제 다운로드, 기기 설치, 실제 플레이 인수는 각각 다른 상태다. 설치 성공이나 기존 저장 유지가 아직 확인되지 않았다. 운영체제 보호 기능을 끄거나 경고를 우회하도록 요구하지 않는다. 설치 경고/호환성 문제가 있으면 진행을 멈추고 표시 문구를 기록한다. 시험 서명 APK이며 스토어 정식 출시가 아니다.

## 재사용할 휴대폰 점검 순서

처음에 기기명, Android 버전, APK 버전/파일명을 적는다. 웹은 브라우저명·버전도 기록한다. 최신 시험 APK의 버전을 확인하고 다음 순서를 한 번 수행한다.

1. 제공된 시험 파일을 내려받아 설치·열기가 되는지 기록한다. 실패하면 경고 문구/스크린샷과 기기 정보를 남긴다. 보호 기능 해제는 점검 조건이 아니다.
2. 새 원정을 시작해 영입·배치·카드 선택을 해 본다. 기존 진행이 있으면 새 원정 확인에서 취소해 보존되는지도 확인한다.
3. 첫 중복이 자연스럽게 나왔을 때 두 갈래 선택과 승급을 확인한다. 첫 영입부터 중복이 보장되는 규칙이 아니므로 나오지 않았다면 '미관측'으로 적고 강제 보장으로 바꾸지 않는다.
4. 메뉴→도움말/설정을 열고 작은 화면의 닫기·확인 버튼을 누를 수 있는지 본다. 새 앱 시작의 QA OFF, 일반 최고3배, QA를 켠 뒤10배와 항상 보이는 QA 표식을 확인한다. QA를 다시 끄면 최대3배여야 한다.
5. 진행 중 홈으로 나갔다 돌아온 뒤 앱을 닫고 다시 열어 '이어하기'를 선택한다. 영웅·카드·웨이브/진행이 재추첨되지 않는지, QA는 OFF이고 이전 고배속은 최대3배로 돌아오는지 적는다. 브라우저는 새로고침과 탭 닫기/재열기를 별도로 검사한다. 앱과 웹의 저장을 서로 같은 저장으로 가정하지 않는다.
6. 소리를 시험하려는 사람이 직접 켠 경우에만 영입·공격·누수·승패 소리, 음소거, 배경/복귀 때 겹침이나 과거 소리 재생을 듣는다. 켜지 않았다면 청취 미검증으로 남긴다.
7. 한 판을 끝까지 진행해 최종 준비 목표, 등장 대기, 실제 보스HP, 처치/미처치 결과 설명, 승패 후 재시작을 확인한다. 도중 패배하면 도달 웨이브와 막힌 이유를 적고 보스 확인은 미관측으로 남긴다.

기록 양식: 기기/OS/빌드 | 설치·열기 | 첫 중복/카드/배치 | QA OFF·3배/QA10배 | 닫기→이어하기 | 직접 켠 소리 | 한 판 결과·보스 인지 | 문제 재현 순서·스크린샷.

## 여전히 열린 인수 문턱

- 최종 웹 WASM 실행·IndexedDB 지속 저장·입력 후 음향의 실제 확인
- Android 실제 다운로드·설치·touch/Back·safe-area·배경/재시작·장시간 성능·발열/배터리와 물리 기기 청취
- 현재 모델 자연 성장에서의 배치/갈래 선택 의미,8갈래 비교,1배속 활동시간과 실제 세션시간 구분
- 동일 빌드로3–5명의 실제 플레이, 보스 목표 인지, 선택 이유, 치명적 문제 수정과 재검증

이 UI 통합 이후에는 새 기능 추가를 멈추고 위 문턱을 닫는다. 미실행·차단·실패를 구분한다. 자동화 원정이나 이미지 수를 사람 수로 세지 않으며, 파일 검증/배포 성공을 전체 완성 판정으로 쓰지 않는다. 친구에게 비공개 실행 접근을 자동 공개하거나 초대하지 않는다.

[2차 보스 공략·채굴 임무](2026-10-03_phase2-mission-proposal.md)는 제안만 유지한다. 새 모드·맵·영웅·영구 자원 경제의 구현 승인이 아니다. 선행 팀 결과와 모든 과거 릴리스 문서는 그대로 보존한다.
