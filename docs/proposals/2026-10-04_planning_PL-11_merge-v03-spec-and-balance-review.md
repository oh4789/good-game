## 3. 문제점과 개선 제안

### P1 — 실버 성장의 기산점을 결제와 선택 확정 사이에서 구분

승인 문서의 ‘구매 이후 팀 처치’는 결제 시점과 카드 확정 시점을 구분하지 않는다. 현재 소스는 `buy_ability`에서 결제/후보만 저장하고, `choose_ability`에서 현재 팀 처치 수를 `kill_start`로 기록한다. 즉 **카드를 선택 확정한 뒤부터 성장**한다. 카드 본문의 ‘획득 이후’, 장부의 ‘획득 후 팀 처치’는 이 동작과 맞는다.

- 확인 예: 팀 처치 100에서 결제 → 창을 닫고 105까지 전투 → 성장 카드 확정. 이 기록의 시작은 105, 즉시 보너스는 +3%p. 106번째 팀 처치 뒤 +3.15%p. 확정 후 80처치에 총 +15%p로 멈춘다.
- 읽은 `MergeContract.gd`의 성장 검사는 시작 처치 수를 장부에 직접 넣고 증가분을 확인한다. 이 사례만으로 결제~확정 사이의 전투까지 검증됐다고 볼 수 없다. 전체 검수에서 해당 경계가 빠졌다고 단정하지는 않는다.
- **권장 문구:** ‘카드 선택을 확정하면 피해 +3%p. 확정 이후 팀 처치마다 +0.15%p, 80처치까지 성장.’
- 제안 범위/효과: 규칙을 바꾸지 않는 문구 명확화로 환급·소급 성장 오해를 줄인다. 작업량은 문서/표시 문구 검토와 좁은 경계 증거 확인 수준이다.
- 채택 상태: 제안. 두리가 현재 동작을 의도와 일치한다고 확인하면 문구를 정합화한다. 결제 직후부터 성장을 의도했다면 동작 변경 결정이 먼저 필요하며 이번 기획에서 고치지 않는다.

### P1 — 공용의 적용 대상을 유지하고 미리보기 산식을 분리

현재 유료 상점 상세 표시명은 이미 ‘해당 영웅 전 성급’이므로 새 UI 전체를 만들 이유가 없다. 향후 짧은 툴팁·검수표에서도 XP는 ‘출전대 공용’, 유료 능력은 ‘비비/탄코/로코 전 성급’을 유지한다. 적용 인원이 0명이어도 결제된 카드는 확정할 수 있고 미래 영입에 유효하다.

PL-10은 안정판 12카드와 최대 3영웅을 대상으로 한 제안이다. 합성 후보는 16개 개체와 성급별 적용/해제가 있어 그대로 통합하면 잘못된 수치를 보여줄 수 있다. 예를 들어 2성에서 XP 화력 한 장은 배율에 `2.20 × 0.04 = 0.088`을 더한다. 화면의 ‘+4%p’만 보고 최종 피해가 직전 값보다 정확히 4% 증가한다고 쓰지 않는다. 합성으로 개체가 3→1로 줄기 때문에 ‘무조건 파티 DPS 상승’도 보장하지 않는다.

제안은 기존 안내의 용어·수식 경계 유지이며 신규 능력, 수치 조정, UI 구현 승인이 아니다. 수치 미리보기를 합성 후보에도 채택할 때만 해당 후보 기준의 별도 대조가 필요하다.

## 5. 기존 밸런스 기록의 독립 재집계

4개 JSON은 baseline 48건, matched-final 48건, 일반 미사용 시드 96건, 에픽 제거 미사용 시드 96건이다. 각 묶음 내부 `(정책, 시드)` 중복 0건, 모든 `state_error`는 빈 문자열이다. 이것은 기록 필드 대조이지 런타임 무결성의 새 인증이 아니다.

전후 48쌍은 정책/시드 키가 일치한다. 성장 정책 5개에서 각 8쌍을 집계하면 다음과 같다. 단위는 초이며 소수 둘째 자리 반올림이다.

| 정책 | 빈 길 시간 평균: 이전 → 후보 | 각 실행의 처치 지연 p90 평균: 이전 → 후보 |
|---|---:|---:|
| 1성 다수 | 204.20 → 152.21 | 1.05 → 3.24 |
| 빠른 2성 합성 | 208.38 → 158.16 | 1.15 → 1.89 |
| 혼합 | 223.05 → 163.68 | 0.99 → 1.99 |
| 비비 능력 집중+다수 영입 | 204.60 → 147.93 | 1.04 → 4.15 |
| 6명 능력 우선 | 219.82 → 154.00 | 0.98 → 4.79 |

성장 정책의 일반 미사용 시드 결과는 합계 80/80 승리, 에픽 제거는 79/80 승리로 공식 보고와 일치한다. 초기 1명 유지 대조군은 두 조건 모두 0/16, 모두 5웨이브 패배다. 이 자동 정책 결과를 사람의 승률이나 최종 난이도 판정으로 쓰지 않는다.

에픽 제거의 유일한 성장 정책 패배는 `ability_focus`, seed `420575404`다. 10웨이브, 보스 처치 true, 325처치·20누수·HP 0, 최소 벽시계 시간 약 503.32초로 기록돼 있다. 보스를 못 잡은 실패가 아니다.

추가로 확인한 비교 한계:

1. 일반 16시드와 에픽 제거 16시드의 교집합은 **0개**다. 전후 비교의 8시드와도 겹치지 않는다. 따라서 80/80 대 79/80만으로 에픽 제거의 인과 효과나 필수성을 말할 수 없다.
2. 빠른 합성 정책은 일반 기록에서 평균 영입 28회·능력 구매 0회, 6명 능력 정책은 영입 5회·능력 구매 19.625회다. 서로 다른 투자 정책이며 같은 예산/같은 명단의 능력 유무 대조가 아니다.
3. 표의 p90은 **각 실행 p90의 산술평균**이다. 전체 적을 합친 p90이 아니다. 처치 지연은 처치된 적 기준으로 누수된 적은 제외되므로 누수와 함께 읽는다.
4. 빈 길 시간·표적 부재 표본은 사람의 지루함이나 손 놓은 시간과 같지 않다. 역할별 피해 비중도 명단·배치·정책의 영향을 받는다.
5. 대표적인 승리 기록은 전투 약 400.17초 + 자동 준비 64초 = 약 464.17초(7분 44초)다. 최장 에픽 제거 실행 약 507.78초(8분 28초). 첫 두 수동 시작 대기와 사람의 선택 시간은 포함하지 않아 실제 세션 길이로 단정할 수 없다.

결론적으로 일반 적 후반 HP와 보스 HP 조정 뒤 빈 길 시간이 줄고 처치 지연이 늘어난 방향은 재집계로 확인된다. ‘엄격한 7분’, ‘에픽 필수’, ‘합성이 항상 우월’, ‘능력 구매 불필요’는 이 자료가 뒷받침하지 않는다. 새 수치 변경은 제안하지 않는다.

## 6. 다른 팀 요청·차단·다음 단계

아래는 문서상 인계 요청이며 수신 팀의 수락·실행 완료를 의미하지 않는다.

| 받을 팀 | 필요한 확인/자료 | 이유와 연결 작업 |
|---|---|---|
| 두리 | 성장 기산점은 현 구현의 ‘카드 확정’이라는 해석 채택 여부. 채택 시 관련 안내 문구 정합화 | PL-11 M02. 규칙 변경 없이 모호함 해소 가능. 결제 기산점을 원하면 별도 결정 필요 |
| 개발/QA, 두리 조정 | M02의 결제~확정 전투 구간과 M04의 수혜자 소멸 후 확정에 대한 기존 사례/로그 연결. 부재 시 이 경계만 보완 | 전체 suite 반복이나 추가 대량 밸런스 실행을 요청하지 않음. 팀 소유 운영 파일은 기획이 수정하지 않음 |
| QA/기기 검수 | 정확한 트랙·빌드로 실제 화면에서 적용 대상, 합성 손실, 화염/저격 선택 이유를 기록 | 소스 기대값과 사람의 이해를 구분. 기존 PL-09 사람 기록 차단을 이어받음 |
| 두리 | 후보 APK 서명 조건 확인 이후의 정확한 전달물 식별과 기기 인수 자료 | 후보 보고의 기존 서명 차단 유지. 기획에서 키 생성·설치·배포를 대신하지 않음 |

**남은 차단:** 실제 3–5명 선택/실패 이유 기록, 안정판 실제 기기/브라우저 인수, 합성 후보의 APK 전달/실기기 인수는 이번에 확보하지 못했다. 미완료를 자동 검수·소스 검토로 닫지 않는다. 접근/서명 요청을 반복하지 않고 기존 담당 경로를 유지한다.

**다음 후보 1 — P0, 새 증거 인수.** 기산점 해석·해당 경계 로그 또는 실제 사람 기록이 들어오면 이번 M01~M08 및 기존 PL-09 표에 대응시켜 증거가 닫는 항목만 갱신한다. 산출물은 입력이 있는 경우의 차이/인수 보고 1개이며, 완료 조건은 트랙·버전·출처·관측·미검증 구분이다. 의존성은 두리/QA의 새 결정 또는 실제 기록이다. 새 증거가 없으면 같은 차단을 다시 문서화하지 않는다.

마지막 완료 지점: 최신 지시·결과 확인 → 후보 소스 식별/읽기 검토 → 288개 원시 기록 재집계 → 해석 경계·인수 기준·담당 요청 정리.
다음 1단계: 새 결정/실행 기록을 받아 해당 경계와 대조. 현재 후보 기능의 재구현이나 새 영웅·카드 확장은 하지 않는다.
