## 3. 현재 성장의 사용자 표현 [제안]
영웅 기본 상태: “승급 0 · 갈래 미선택”.
첫 중복: “비비 승급 +1 — 이번 원정의 갈래를 선택하세요.”
추가 중복: “비비 승급 2 — 공격력 성장”.
낮은 상한을 암시하는 “MAX”, 3성 고정 별 슬롯, 승급 재료 게이지는 사용하지 않는다.
카드 설명: “경험치로 보조 능력을 강화합니다.”
영입 설명: “고철로 동료를 영입합니다. 중복 영웅은 즉시 승급합니다.”
새 런 안내: “영웅과 강화는 새 원정에서 초기화됩니다. 최고 웨이브 기록은 남습니다.”

승급 공격력 표시는 기본 공격력 기준 누적 +18%p다.
승급0/1/2/3/4/5/6의 해당 배율은 1.00/1.18/1.36/1.54/1.72/1.90/2.08.
이는 승급 항목만의 산술값이며 카드·갈래·방어 계산을 합친 최종 피해가 아니다.
실제 합산 순서는 코드를 확인해야 한다. UI가 독립 계산으로 다른 최종 피해를 표시하지 않도록 한다.
특수 효과 개수가 승급2에서 제한돼도 승급3 이후 수치 성장은 계속됨을 정보 화면에서 구분한다.

## 4. 첫 중복 선택 화면 [제안]
| 영웅 | 선택지 1 설명 | 선택지 2 설명 |
|---|---|---|
| 비비 | 연사 — 한 표적에 공격을 집중합니다 | 탄막 — 여러 표적을 처리합니다 |
| 탄코 | 폭발 — 넓은 범위의 적을 공격합니다 | 소이 — 불길로 지속 피해를 줍니다 |
| 로코 | 유도 — 강한 표적을 노립니다 | 관통 — 일직선의 적을 꿰뚫습니다 |

구체 배율·대상 수·화염 지속시간은 실제 구현값을 받아 표시한다. 사거리 증가나 파쇄처럼 확인하지 않은 효과를 문구에 추가하지 않는다.
공통 안내: “선택한 갈래는 이번 원정 동안 유지됩니다.”
첫 탭은 설명, 별도 선택 버튼은 확정. 모바일에서 두 설명과 선택 버튼을 모두 읽을 수 있게 한다.
선택 중 전투 정지를 권장하되 현재 구현과 다르면 차이로 보고한다.

동시 사건 처리 후보:
1. 영입 거래·승급 수치 반영은 한 번 확정한다.
2. 첫 중복일 때만 갈래 선택 요청을 만든다.
3. 결과 확정이 없으면 갈래 선택을 먼저 처리하고, 대기 경험치 카드를 이어서 처리한다.
4. 같은 영웅의 추가 중복으로 갈래 선택을 다시 열지 않는다.
5. 숨김/정지/화면 재표시로 영입이나 승급을 다시 지급하지 않는다.
6. 선택 중 다른 영입 입력은 받지 않는 후보로 시작한다. 보류 자동 실행은 하지 않는다.

이 순서는 미정 UI 충돌의 해소 제안이며 기존 엔진 동작을 검증한 보고가 아니다.
선택 화면의 필요 데이터를 보존하는 것은 현재 런 메모리 처리다. 중간 런 영구 저장 기능을 새로 요구하지 않는다.

## 5. 영입 비용 검산 — 실제 수입과 분리
현재 임시 비용표에서 계산한 누적 지출:
| 영입 횟수 | 이번 비용 | 누적 비용 |
|---:|---:|---:|
|1|12|12|
|2|12|24|
|3|24|48|
|4|30|78|
|5|36|114|
|6|42|156|
|7|48|204|
|8|54|258|
|9|60|318|
|10|66|384|

3회째부터 n회째 비용 = 24 + 6(n-3).
n>=2일 때 누적 비용 = 24 + (n-2)(3n+15).
최초 두 번으로 미보유 2종을 얻고 기본 3종이 모두 갖춰지는 현재 흐름에서는 3회째 영입이 첫 승급 기회다.
따라서 다른 지출이 없고 초기 고철이 0인 조건에서 누적48 고철 획득이 첫 갈래 선택의 필요 지점이다.
이는 “48킬”이나 “몇 웨이브”를 의미하지 않는다. 실제 보상·초기 자원을 확인해야 한다.
뽑기 확률을 확인하지 않았으므로 영웅별 승급 확률과 전원 갈래 완성률은 산출하지 않는다.

관측 요청: 첫 영입, 3인 확보, 첫 중복, 영웅별 첫 갈래, 추가 승급의 시각·웨이브·누적 고철.
첫 갈래가 너무 늦으면 먼저 실제 획득/소비/버튼 발견 여부를 확인한다. 바로 무료 중복이나 카드 갈래 해금을 추가하지 않는다.

## 6. 난이도 검토 — 현재 보고에 대응
통합 문서가 보고한 40개 시나리오는 전부 HP20 승리다.
이 사실은 해당 시나리오에서 여유가 크다는 근거이며 모든 사람의 승률100%나 재미 실패를 뜻하지 않는다.
브라우저·휴대폰 미검수는 별개다. 자동 테스트가 잘되는 것만으로 실제 조작 합격을 선언하지 않는다.

우선순위:
A. 실제 브라우저 시작→영입→첫 중복 갈래→보조 카드→보스→결과→새 런 연결.
B. 최고 웨이브 기록의 재접속 유지와 새 런 초기화.
C. 현재 값으로 갈래별 공격 기회·누수·완주시간·첫 갈래 시점 기록.
D. 원인이 확인된 뒤 한 변수씩 시험 조정.

3명 각2갈래의 조합은 8개다. 우선 같은 배치·시드에서 8조합을 비교한다.
개발용 갈래 강제 선택은 동작 차이 검수에만 쓰고 자연 영입에서 해당 조합을 얻을 확률이나 성장 체감으로 해석하지 않는다.
자연 영입 비교는 별도 기록하며 강제 고철·카드·승급 여부를 명시한다.

| 관측 | 먼저 확인 | 시험 후보 |
|---|---|---|
| 모든 갈래에서 적이 초반에 사라짐 | 실제 공격력·표적 중복·피해 중복·적 HP | 오류 제외 후 일반 적 HP +10% 비교 |
| 일반전은 충분하나 보스가 즉시 사망 | 보스 HP·집중 피해·갈래별 추가타 | 보스 HP만 +10% 비교 |
| 소이만 역할을 못함 | 장판에 머무는 시간·첫 틱·중첩·표적 밀도 | 원인 확인 후 해당 항목 하나 조정 |
| 관통만 과도하게 강함 | 한 적 중복 명중·관통 대상·추가타 상한 | 버그 여부 먼저 판정 |
| 승급 뒤부터 급격히 쉬워짐 | +18%p 선형 적용·효과 개수 제한 | 구현 오류 수정 후에만 성장값 비교 |
| 첫 갈래가 늦음 | 누적48 도달과 실제 영입 시점 | 비용 또는 보상 한 항목만 비교 |

+10%는 실험 후보이지 채택된 패치가 아니다. HP/이동속도/스폰 밀도를 동시에 바꾸지 않는다.
이동속도 변경은 사거리 체류시간과 지속 피해까지 바꾸므로 첫 일괄 조정값으로 쓰지 않는다.
목표는 억지 패배율 확보가 아니라 배치·갈래 선택의 차이가 읽히는지 확인하는 것이다.

## 7. 역할별 인계와 완료 기준
개발1팀/통합: 기준 문서의 실제 소스 버전으로 판정·승급·2갈래·보조 카드를 확인. 구규칙 혼입 여부와 실제 카드 목록/영입 확률/자원 수입을 기록.
개발2팀: 궁극기 버튼·3성 상한·중복 재료·최대성 환급·핵심 카드 해금 UI가 현행 화면에 남았는지 확인. 존재를 추정해 삭제하지 말고 실제 화면 기준으로 수정.
디자인: 3영웅×2갈래를 현재 제작 기준으로 사용. 특히 탄코 소이와 로코 관통의 외형 구분. 새 영웅은 별도 채택 대기.
음향: 수동 궁극기용 음원을 그대로 버튼과 연결하지 않는다. 승급·갈래 선택·현재 공격 사건에 맞는 재사용 후보를 구분.
QA: 구규칙 기대값을 v0.3에 적용하지 않는다. 첫 중복1회 선택·추가 중복 성장·승급3 이상 수치 증가·효과 개수 제한·새 런 초기화·최고 기록 보존 검수.
기획: 실측 후 이전 값/새 값/원인/비교 결과를 가진 작은 수정안 작성.

핵심 검수:
- 첫 중복 즉시 승급1, 2갈래 선택1회.
- 두 번째 중복은 승급2이며 기존 갈래 유지.
- 세 번째 중복은 승급3이며 공격력 성장 지속, 효과 개수는 채택된 상한 준수.
- 카드만으로 갈래를 열거나 중복 영입을 지급하지 않음.
- 새 런에 이전 승급·갈래·카드·자원 없음, 최고 웨이브 기록은 유지.
- 브라우저 재접속으로 중간 런 이어하기를 잘못 약속하지 않음.
