## 1. 기준 확인과 작업 경계

확인한 최신 공개 기준은 `WORK_START_HERE`, `CURRENT_IMPLEMENTATION`, 디자인 작업 지시서, 실험 v0.4.2 가독성 보고다. 현재 실험은 v0.4.2이며 320×568·390×740·844×390 네이티브 렌더 검토가 있으나, 실제 휴대폰·사람의 읽기·터치 합격은 계속 OPEN이다.

DS-09는 별도 검토 PR에서 아직 미병합 상태다. 이 문서는 DS-09의 `R0 코앞 → R2 중앙 개방`을 **제안 입력**으로 사용하며 메인 구현 사실처럼 기록하지 않는다. 기존 디자인 지시서의 DS-07 우선 작업도 대체하지 않는다. 사용자가 DS-09 후속 후보 중 DS-10을 직접 선택했기 때문에 독립 정적 인계물로 진행했다.

### 현재 결정 — 변경하지 않음

1. 적은 사각형 바깥 경로를 돌고 영웅은 안쪽 4×4에 배치한다.
2. 선택한 영웅 3종 중 1명만 시작 시 무작위 소환된다.
3. 처치 고철로 영입·영웅별/성급별 능력을 구매한다. XP·웨이브 카드로 되돌리지 않는다.
4. 현재 전투 구현 범위는 2성까지이며 3성은 잠긴 미래 제안이다.
5. 운영 UI·게임 코드·배포 파일은 두리가 소유한다.

### 이번 새 제안 — 미확정

- 첫 영웅 배치 때 공격 가능한 경로가 0인 칸은 선택 불가로 표시한다.
- 현재 가설 지형에서는 외곽 12칸을 배치 가능, 중앙 4칸을 잠김으로 표시한다.
- 영웅 선택 시 원형 사거리만 보여주지 않고 **실제로 닿는 경로 구간**을 같이 강조한다.
- 사거리 구매 전에 현재 R0와 강화 후 R2를 동시에 표시한다.
- 중앙 잠금 해제 조건·비용·정확한 사거리 수치는 사용자와 두리 검토 전 확정하지 않는다.

## 2. 권장 정책

### 2.1 첫 영웅만 동적 도달 마스크 적용

하드코딩된 `외곽 12칸`보다 실제 표적 판정과 같은 함수로 각 칸의 `reachable_segments`를 계산하는 방식을 권장한다.

```text
첫 영웅 배치 가능 = reachable_segments(cell, hero, current_range) > 0
```

현재 DS-09 가설에서는 중앙 4칸이 0이어서 잠기고 외곽 12칸이 열린다. 지형·사거리·영웅이 바뀌면 개수도 자동으로 바뀐다. 첫 영웅 이후에는 중앙을 영구 금지하지 않고, 이동/추가 영입 때 `현재 공격 불가` 경고 또는 실제 도달 여부를 다시 계산한다.

### 2.2 원이 아니라 길을 강조

사각 경로에서는 범위 원이 길에 닿아도 실제 표적 샘플·공격 형태에 따라 공격하지 못할 수 있다. 따라서 UI는 다음을 동시에 보여준다.

- 점선 원: 이해를 돕는 거리 보조선.
- 굵은 경로 구간: 실제 공격 판정이 가능한 길.
- 칸 상태: 실선 `+`는 선택 가능, 빗금·자물쇠는 잠김, 점선 `!`는 현재 공격 불가.
- 수치: `공격 가능 1구간`, `R0 1.20칸 [가설]`처럼 텍스트로 재확인.

### 2.3 구매 전 전후 비교

사거리 구매 상세에서 현재 R0는 붉은 점선, 강화 후 R2는 초록 점선으로 겹쳐 표시한다. 경로도 현재/강화 후를 같은 화면에서 비교한다. `발사 간격 유지`, `탄창/장전 아님`을 함께 적어 성장축 혼동을 막는다.

## 7. 두리·개발2 인계 데이터 계약

시안 구현 전 아래 값이 현재 게임의 실제 표적 함수에서 제공돼야 한다.

| 필드 | 용도 |
|---|---|
| `placement_phase` | 첫 영웅/일반 이동/합성 재배치 구분 |
| `hero_id`, `star`, `branch` | 영웅별 공격 형태·성급 구분 |
| `cell_id`, `cell_center` | 4×4 실제 좌표 |
| `range_units`, `range_tier` | 현재/다음 사거리 |
| `attack_shape` | 원형·직선·원뿔·경로 설치 등 |
| `reachable_segments[]` | 실제 공격 가능한 경로 구간·폴리라인 |
| `is_cell_selectable` | 첫 배치 확정 가능 여부 |
| `unreachable_reason` | 사거리 부족·표적 없음·특수 규칙 |
| `preview_current`, `preview_next` | 구매 전 전후 비교 |
| `cost_scrap` | 실제 고철 비용. 없으면 UI에 가설값을 넣지 않음 |

**중요:** UI 전용 근사 계산을 따로 만들지 말고 전투 표적 판정이 반환한 결과를 시각화해야 한다. 두 계산이 갈리면 `보이는 사거리와 실제 공격이 다름`이라는 치명적 오해가 생긴다.

## 8. 계열별 표시 확장 조건

DS-10의 원형 시안은 공통 레이아웃 예시다. 실제 6계열에서는 다음 오버레이가 필요하다.

- 지뢰 공병: 설치 가능한 경로점, 무장 전/후, 활성 지뢰 수.
- 탱크: 착탄점과 폭발 반경.
- 비행기: 출격선·폭격 띠·경고 시간.
- 우주선: 유도 대상 또는 관통 직선.
- 로봇: 부채꼴·지속선 끊김 조건.
- 드론: 분산 대상·표식 대상.

이 표현은 새 공격 효과를 확정하는 것이 아니라 DS-09 공격 형태가 채택될 경우 필요한 UI 입력 조건이다.

## 10. 우려점

1. **중앙 고정 잠금 위험:** 지원형·설치형까지 영구 잠그면 전략을 줄인다. 첫 영웅의 동적 도달 마스크로 한정하는 것이 안전하다.
2. **공격 형태 중복 계산:** 원형 근사와 실제 직선·원뿔·지뢰 판정이 다르면 UI 신뢰가 무너진다.
3. **낮은 화면 높이:** 320×568에서는 현재 하단 패널이 그대로 들어가지 않는다. 스크롤 또는 축약 상태가 필요하다.
4. **전투 가림:** 사거리 오버레이는 선택·구매 미리보기 때만 표시하고 평상시 전투를 가리지 않아야 한다.
5. **잠금 해제 조건:** `첫 사거리 구매`, `R2 도달`, `도달 구간 1개 이상` 중 어느 것을 쓸지 미결정이다. 구현 전에 사용자 결정 또는 실제 좌표 시험이 필요하다.
