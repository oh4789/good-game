## 2. 새 기획 A — 배치 전에 판단 근거 제공 [제안]

### 준비 화면
- 상단: 현재 웨이브/총 웨이브, 공용 HP, 다음 적 대표 2종과 총 등장 수.
- 경로: 입구·이동 방향·퇴장 지점을 항상 구별. 장식보다 가독성 우선.
- 영웅 선택: 사거리, 기본 표적 규칙, 실제로 공격 가능한 경로 구간을 표시.
- 영입 대기: '다음 전투에 배치 가능' 및 미배치 인원 표시.
- 이동: 드래그와 '영웅 선택 → 칸 누르기'를 모두 지원. 점유 칸은 두 영웅 교환을 제안하되 보드 밖 드롭은 원위치.
- 시작: 미배치 영웅이 있으면 시작 버튼 옆에 안내하되 이미 출전한 영웅이 있다면 시작을 강제 차단하지 않는다.
- 준비 중 타이머는 강제 시작에 사용하지 않는다.

### 상황별 안내 문구
| 상황 | 안내 |
|---|---|
| 첫 배치 | 영웅을 놓으면 공격 가능한 길이 표시됩니다. |
| 첫 영입 완료 | 새 동료가 도착했습니다. 다음 준비 시간에 배치하세요. |
| W4 장갑 | 장갑 적 등장! 파쇄 뒤에 아군 공격이 이어지게 배치해 보세요. |
| W5 질주 | 빠른 적 등장! 출구 쪽 공격 구간을 확인하세요. |
| 중앙에서 공격 경로 없음 | 이 위치에서는 기본 공격이 길에 닿지 않습니다. |

안내는 최초 해당 상황에 한 번만 표시하고 다시 열 수 있게 한다. 사거리 안내는 실제 공격 판정과 같은 데이터를 사용한다. 모든 칸을 유효하게 보이게 하려고 임의로 사거리를 늘리지 않는다.

## 3. 새 기획 B — 강화 선택에 이유와 결과 표시 [제안]

전용 카드 이름은 02의 9종을 유지한다. 이번에 다른 카드 9종을 추가하지 않는다.

카드 필수 정보:
- 대상 영웅, 효과 한 줄, 현재 → 선택 후 효과, 보유 단계/상한.
- 해당 카드의 활용 상황 태그 1개: 단일 / 군집 / 장갑 / 공격 빈도.
- 선행 조건·상한 미충족 카드는 선택 풀에서 제외.
- 숫자가 정해지지 않은 효과를 임의로 UI에 확정값으로 쓰지 않는다.
- 선택 후 짧은 영웅 강조와 변경 효과 아이콘을 표시. 전투 재개를 별도 연출로 지연하지 않는다.

예시 문구:
- 관통 탄환: '앞의 적을 맞힌 탄환이 뒤의 적까지 관통합니다.' 관통 수·감쇠율은 수치 명세에서 받아 표시.
- 지연 소폭발: '포탄이 터진 자리에 잠시 뒤 작은 폭발이 발생합니다.' 지연·범위·피해는 명세 필요.
- 오래 남는 파쇄: '장갑 약화가 더 오래 유지됩니다.' 기본 4초 시험안과 강화 후 시간을 비교.

카드 추첨은 기존의 출전 영웅 제한을 유지한다. '추천'을 자동 정답으로 표시하지 않는다.
유효 카드 부족을 해결할 공용 카드 종류·반복 상한은 전투 수치 담당이 먼저 명세한다. UI 담당이 임의의 무한 강화나 무료 영입 카드를 만들지 않는다.

## 4. 새 기획 C — 궁극기는 한 번 눌러 전술 사용 [제안]

첫 시험은 별도 조준 모드 없이 영웅별 버튼 1회로 사용한다. 수동 조준은 후속안으로 보류한다.

| 영웅 | 사용 방식 | 누를 때 유효 표적이 없음 | 사용 중 정보 |
|---|---|---|---|
| 비비 | 현재 유효 표적을 유지하며 과열 난사. 이탈 시 기본 표적 규칙으로 재선정 | 사용하지 않고 충전 보존 | 남은 지속 시간과 과열 표시 |
| 탄코 | 발동 시 사거리 내 최대 밀집 지점을 고정하여 시간차 포격 | 사용하지 않고 충전 보존 | 착탄 예고 원. 이동한 적을 자동으로 전부 따라가지 않음 |
| 로코 | 장갑 적 우선, 동률이면 진행률이 높은 적에 파쇄탄 | 사용하지 않고 충전 보존 | 표적과 파쇄 아이콘 |

- 충전량·시간·피해·탄코 포격 횟수는 전투 수치 담당이 시험값으로 제시한다.
- 충전이 부족하거나 카드·준비·결과 화면이면 사용 불가. 비활성 사유를 짧게 표시.
- 유효 발동을 접수한 뒤 표적이 죽어도 충전을 환급하지 않는 것을 기본안으로 제안. 로코 탄의 표적 소실 시 소멸/재추적은 명세에서 하나로 고정해야 한다.
- 발동 연타로 중복 소모·중복 효과가 나지 않아야 한다.
- 정지 중에는 충전·지속·지연 포격 시간이 모두 정지한다.
- 궁극기 피해가 카드 추가타를 유발하는지 수치 명세에 반드시 명시한다. 기본안은 기본 공격 전용 추가타 미발동.
- 웨이브 종료 시 지속 중 효과를 종료하고 남은 발사 예약을 취소하는 시험안을 제안한다. 충전 잔량은 유지한다. 기존 빌드와 차이를 먼저 기록한다.

## 5. 새 기획 D — 실패 이유를 다음 배치로 연결 [제안]

결과 화면은 승패, 도달 웨이브, 플레이 시간, 누수 피해를 먼저 표시한다.
그 아래 영웅별 실제 피해·궁극기 사용 횟수·선택 카드와 적 유형별 누수 수를 보여준다.
실제 피해는 과잉 피해를 제외한다. 지원 효과를 피해에 임의로 합산하지 않는다.

한 줄 팁은 기록으로 판별 가능한 사실만 사용한다:
- 질주 적의 누수 피해가 가장 컸다면 '빠른 적에게 가장 많은 HP를 잃었습니다. 출구 쪽 공격 구간을 확인해 보세요.'
- 영입 대기가 마지막 전투까지 남았다면 '영입한 동료 중 배치하지 않은 동료가 있습니다.'
- 유효 표적이 있었고 완충 상태였던 궁극기를 한 번도 쓰지 않았다면 '사용 가능한 궁극기가 남았습니다.'
- 조건에 맞는 기록이 없으면 일반 팁을 표시. 패배를 무조건 사용자 실수로 단정하지 않는다.

동점 우선순위는 누수 유형 → 미배치 → 궁극기로 한다.
'다시 시작'은 런 상태 초기화 규칙을 따르고 결과에서 자동 과금·광고·영구 강화로 연결하지 않는다.

산출물: 변경 커밋, 실행/미리보기 방법, 채택 제안 목록, 데이터·이벤트 계약, 검증 결과.

소유: 게임 코드 변경과 다른 담당 산출물 통합. 디자인·음향 담당이 같은 게임 파일을 동시에 수정하지 않는다.

### Work 3 — 디자인·UI·애니메이션

> 톱니 공방 시험안에 맞춰 준비·전투·카드 선택·결과 화면 4종을 설계하고 영웅 3명의 대기·공격·장전, 적 4종의 이동·피격·사망, 보스의 장갑 전환을 구별해주세요. 실제 게임 화면 비율과 엔진의 이미지 규격을 개발 담당에게 받은 뒤 제작하세요. 투명 여백, 원점, 프레임 크기, FPS, 파일명, 사용 위치를 명세하세요. 예쁜 컨셉 그림과 바로 사용할 스프라이트를 구분하고, 무기·유령·폭발 잘림을 확인하세요. 게임 코드는 수정하지 마세요.

산출물: 화면 시안 4종, 실제 사용 가능한 우선 에셋, 에셋 목록·미완료 목록.
우선순위: 비비 공격 생동감 → 경로/사거리/영입 대기 → 나머지 영웅 → 적·보스.
완료 기준: 지원 최소 화면 폭(미정이면 360 CSS px 시험)에서 버튼 겹침·경로 가림을 검사하고, 모든 동작 프레임의 무기와 효과가 잘리지 않는다. 터치 영역은 44×44 CSS px 이상을 시험 기준으로 사용한다.

### Work 4 — 음향
지시:
> 기관총·대포·로켓의 구분을 먼저 만들고 피격/사망·영입·강화 선택·궁극기 준비·누수·승패 효과음을 준비해주세요. 파일별 용도·길이·반복 여부·권리/출처를 명시하세요. 실제 오디오 파일이 없는 항목은 설계만 완료라고 표시하세요. 기관총 동시 재생 제한과 폭발 우선순위를 제안하고, 카드 정지·앱 비활성·음소거·재시작 동작을 개발 이벤트와 맞추세요. 게임 코드는 수정하지 마세요.

산출물: 오디오 파일 또는 제작 상태, 사운드 이벤트표, 볼륨·동시 재생 권장값.
완료 기준: 세 병종을 소리로 구분하고 연사 시 과도한 중첩이 없으며, 음소거 후에도 시각 정보로 핵심 상태를 알 수 있다.
우선순위: 전투 SFX → UI/누수 → 짧은 반복 BGM. BGM 제작 때문에 핵심 효과음을 미루지 않는다.

### Work 5 — QC/QA·밸런스 실측
지시:
> 검토할 빌드 커밋과 실행 환경을 먼저 고정해주세요. 03의 Q01~Q20 및 05의 생성·보스 종료 조건을 검수하고, 이 문서의 배치 안내·카드 표시·궁극기·결과 팁을 확인해주세요. 탄코→로코와 로코→탄코 첫 영입 순서를 모두 시험하세요. 기능 문제가 해소된 뒤 최소 20런에서 전투/준비/카드 시간, 누수, 영입 시점, 카드 횟수를 기록하세요. 실행하지 못한 항목은 미검수로 남기고 코드나 수치를 임의 변경하지 마세요.

산출물: 재현 절차와 기대/실제/심각도, 20런 원자료, 수정 우선순위.
완료 기준: 진행 불가·중복 지급·진영 혼입·보스 종료 오류 0건. 6~8분은 측정된 완료 런의 분포로 보고한다.
20런은 두 영입 순서 각 10런을 기본으로 하고 서로 다른 시드와 배치 비교를 포함한다. 승률은 이 작은 표본의 관측값으로만 표시한다.
성능은 기기·브라우저·최대 활성 적 수와 함께 기록하며 모든 휴대폰에서 부드럽다고 일반화하지 않는다.

## 8. 순서와 인계 계약 [제안]

1. 메인 개발이 기준 소스·현재 기능·엔진·화면 규격을 확인한다.
2. 전투 설계는 데이터 명세, 디자인은 규격에 맞는 시안, 음향은 이벤트 목록을 준비한다.
3. 메인 개발이 처치→영입→성장 핵심 기능을 연결한다.
4. 10웨이브·영웅별 역할·궁극기를 연결하고 디자인·음향을 반영한다.
5. QA 기능 검수 후 밸런스 20런을 수행한다.
6. 기획팀이 기록을 받아 한 번에 한 축(HP/생성 간격/비용 등)씩 수정안을 새 문서로 낸다.

공유할 최소 ID: hero_id, enemy_type, card_id, wave_id, run_id, seed, build_commit.
공유할 최소 사건: enemy_killed, enemy_leaked, recruit_resolved, hero_deployed, card_selected, ultimate_cast, wave_started, run_finished.
동일 사건의 재처리 방지 방법은 개발 담당이 정의한다. 오디오·시각 효과가 보상을 다시 지급하는 구조로 만들지 않는다.
측정 시간은 combat/prepare/card/pause로 분리하며 중첩 집계하지 않는다.

## 9. 이번 범위 밖 및 미결정

- 영구 수집·영구 강화·두 번째/세 번째 진영·추가 영웅·상점·시즌·과금은 이번 시험판의 필수 작업으로 추가하지 않는다.
- 시작 1명과 첫 두 영입 보장, 기본 3종의 최종 이름, 최대 승급 환급률은 제안 상태.
- 실제 소스 위치·기준 빌드·개발 엔진·기존 저장 구조·최소 지원 기기는 개발 인계 때 확인.

- 다른 Work의 작업 시작/완료는 해당 Work의 응답이나 커밋으로 확인한다.
