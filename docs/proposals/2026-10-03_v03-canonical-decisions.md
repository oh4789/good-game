# 밤길 원정대 v0.3 현재 구현 기준과 두리 검수 확정 사항

- 작성일: 2026-10-03 UTC
- 문서 종류: 현재 결정 기준 및 Work 인계 문서
- 정리·구현 통합 담당: 두리
- 최종 결정권자: 사용자
- 적용 범위: 사각 순환형 타워디펜스 v0.3
- 자료실: 공개 저장소 `oh4789/good-game`
- 기존 자료 확인 기준: [`efff927`](https://github.com/oh4789/good-game/commit/efff92707ae4f40fb01c028ce669164244ba5e93)

현재 작업은 **자동 전투, 첫 중복 즉시 승급과 2갈래 선택, 이후 중복마다 계속 성장하는 3영웅 시험판**을 기준으로 한다. Work는 새 기획·디자인·음향·QA 문서를 만들기 전에 이 문서를 먼저 읽는다.

기존 문서는 기록으로 보존한다. 기존 문서의 수동 궁극기, 3성 상한, 중복 재료 누적, 카드로 핵심 갈래를 여는 규칙은 아래 현재 기준에 적용하지 않는다. 이 정리는 사용자가 승인한 현재 방향을 맞추기 위한 것이며, 이후 사용자의 새 결정을 제한하지 않는다.

## 1. 상태 표시와 읽는 순서

이 문서에서는 상태를 다음과 같이 구분한다.

- **확정 방향**: 현재 작업이 따라야 할 게임 규칙.
- **현재 구현**: v0.3에 반영된 범위. 모든 플랫폼에서 검증됐다는 뜻은 아니다.
- **임시 구현 수치**: 기능 시험을 위해 채택한 값. 사용자의 영구적인 밸런스 결정으로 취급하지 않는다.
- **후속 제안**: 별도 검토와 채택 기록이 필요한 아이디어.
- **미검증**: 실행 또는 실기 증거가 아직 없는 항목.

읽는 순서는 이 문서의 현재 규칙 → 구현·검수 범위 → 충돌표 → 필요한 분야의 기존 자료다. 파일 날짜나 번호가 더 최신이라는 이유만으로 제안을 확정 규칙으로 바꾸지 않는다.

## 2. 확정 방향

### 전장과 한 판의 흐름

- 적은 사각형 바깥 경로를 한 바퀴 돌면 공용 HP에 피해를 주고 퇴장한다.
- 영웅은 안쪽 3×3 칸에 배치한다. 최대 출전 인원은 3명이며, 배치 변경은 웨이브 사이 준비 시간에 한다.
- 한 런은 한 진영으로 진행한다.
- 영웅은 자동으로 공격한다. **플레이어가 직접 누르는 수동 궁극기는 사용하지 않는다.**
- 한 판의 목표 시간은 약 7분이다. 이는 설계 목표이며, 이번 검수로 실사용 플레이 시간과 재미가 확정된 것은 아니다.

### 영입과 런 초기화

- 적 처치로 얻은 별도 자원으로 영웅을 뽑는다.
- 뽑은 영웅과 그 성장은 해당 런에서만 유지한다.
- 새 런에서는 영웅 획득, 승급, 선택한 갈래, 카드 강화, 경험치와 영입 자원을 초기화한다.
- 현재 범위에 런 밖 영구 영웅 수집이나 계정 공격력 성장을 넣지 않는다.

### 중복 영웅과 갈래 선택

1. 같은 영웅을 처음 중복 획득하면 재료를 모으는 대기 단계 없이 **즉시 승급 1단계**가 된다.
2. 이때 그 영웅의 **2갈래 중 하나를 선택**한다.
3. 선택한 갈래는 그 런 동안 유지한다.
4. 이후 같은 영웅을 중복 획득할 때마다 승급이 1단계씩 오른다.
5. 3성처럼 실플레이에서 금방 닿는 낮은 승급 상한을 두지 않는다. 높은 승급에서도 수치 성장은 이어가되, 발사체·동시 효과 개수는 성능과 가독성을 위해 제한할 수 있다.
6. 낮은 최대 승급에 도달한 뒤 중복 뽑기를 고철 환급으로 대체하는 규칙은 정상 성장 흐름에 넣지 않는다.

여기서 승급 단계는 중복 획득으로 오른 횟수를 뜻한다. 기존 문서의 1성·2성·3성과 섞어서 표기하지 않는다.

### 경험치 카드와 뽑기의 분리

- 처치 경험치가 쌓이면 강화 카드 3개 중 1개를 고른다.
- 카드는 공격력·사거리·공격 속도 같은 **보조 강화**를 담당한다.
- 공격 방식의 핵심 갈래는 첫 중복 승급 때 선택한다. 기초 카드 → 핵심 카드 → 완성 카드의 연쇄를 현재 갈래 해금 조건으로 사용하지 않는다.
- 처치 자원은 별도 영입 뽑기에 사용한다. 경험치 카드에서 영웅을 영입하지 않는다.
- 처치 기반 성장으로 전환한 뒤 웨이브 종료에 같은 성장 보상을 다시 지급하지 않는다.

## 3. 현재 영웅과 2갈래

현재 구현 범위는 톱니 공방의 비비·탄코·로코 3종이다. 이 표의 갈래는 첫 중복 승급 때 고르는 선택지다.

| 영웅 | 병종 | 갈래 1 | 갈래 2 |
|---|---|---|---|
| 비비 | 기관총병 | 한 표적을 집중해서 빠르게 공격하는 연사 | 여러 표적을 처리하는 탄막 |
| 탄코 | 대포병 | 넓은 범위의 적을 처리하는 폭발 | 불길과 지속 피해를 남기는 소이 |
| 로코 | 로켓병 | 보스 등 강한 표적을 노리는 유도 | 일직선의 적을 꿰뚫는 관통 |

기존 확장안에서 새 화염 영웅과의 역할 중복을 이유로 탄코의 소이 갈래를 제외한 제안은 현재 3영웅 규칙을 변경하지 않는다. 로코를 장갑 약화 전용 영웅으로 규정하거나, 세 영웅에 대표 1갈래만 적용하는 제안 역시 현재의 2갈래 선택을 대체하지 않는다.

## 4. v0.3 현재 구현과 임시 수치

다음은 현재 시험판의 구현 값이다. 기능을 시험하기 위해 사용하고 있으며 최종 경제·난이도 수치로 고정하지 않는다.

| 항목 | 현재 값 | 상태 |
|---|---|---|
| 초기 영입 | 처음 두 번은 미보유 영웅을 각각 12 고철로 영입 | 임시 구현 수치와 영입 보장 |
| 이후 뽑기 비용 | 세 번째 24 고철, 이후 뽑기마다 6 증가 | 임시 구현 수치 |
| 승급 공격력 | 승급마다 기본 공격력 기준 +18%p 누적 | 임시 구현 수치 |
| 특수 효과 개수 | 개수 증가는 승급 2단계까지 반영하고 제한 | 임시 구현 수치와 성능 제한 |
| 영웅 성장 | 첫 중복 즉시 승급·2갈래 선택, 이후 중복마다 승급 | 현재 구현 |
| 전투 조작 | 수동 궁극기 없이 자동 전투 | 현재 구현 |
| 저장 | 최고 도달 웨이브 기록, 중간 런 이어하기 없음 | 현재 구현 범위 |

승급마다 +18%p는 직전 단계 공격력에 1.18을 반복해서 곱한다는 뜻이 아니다. 특수 효과 개수의 제한도 승급 자체를 2단계에서 끝낸다는 뜻이 아니다.

처음 두 영입의 보장 방식과 위 숫자들은 관측 결과에 따라 조정할 수 있다. 조정할 때는 이전 값, 새 값, 이유와 비교 결과를 함께 기록한다.

## 6. 아트와 음향의 현재 경계

- 현재 화면의 아트는 프로토타입이다.
- 비비 컷아웃 동작 데모는 별도의 검토 자료이며, 현재 게임에 통합 완료된 애니메이션으로 보고하지 않는다.
- 디자인 원화, 동작 연구, VFX 명세는 실제 사용 파일과 구분한다.
- 음향 제작 문서와 제작 완료 보고는 파일 인수, 청취, 게임 이벤트 동기화 검수와 구분한다.
- 새 아트·음향을 적용할 때는 실제 파일 위치, 포맷, 사용 조건, 이벤트 연결과 확인 결과를 남긴다.

## 8. 역할과 새 문서 작성 방법

### 역할

- **사용자**: 게임 방향과 중요한 변경을 최종 결정한다.
- **두리**: 메인 구현·통합과 현재 기준 정리를 맡는다. 기존 승인 범위 안에서 구현을 연결하고 충돌·검수 결과를 보고한다.
- **Work 기획·디자인·음향·QA**: 제안과 제작 자료, 검수 근거를 작성한다. 제안 문서 작성만으로 승인된 게임 규칙이 변경되지는 않는다.

현재 기준과 다른 좋은 아이디어가 있으면 차이와 기대 효과를 제안으로 남긴다. 두리의 통합 역할도 사용자의 이후 선택을 대신하지 않는다.

### Work가 작업을 시작할 때

1. 이 문서와 실제 대상 버전·기준 커밋을 먼저 확인한다.
2. 작업을 현재 규칙의 구체화인지, 구현 오류 수정인지, 규칙 변경 제안인지 구분한다.
3. 충돌이 있으면 어떤 규칙과 어디서 달라지는지 표시하고 채택 여부를 확인한다.
4. 기존 문서 전체를 새 기준으로 간주해 코드나 다른 문서에 자동 반영하지 않는다.
5. 실행하지 않은 기능은 미검증으로, 실제 파일을 전달하지 않은 에셋은 미인수로 표시한다.

### 저장과 인계

- 새 문서는 `docs/proposals/` 아래에 `YYYY-MM-DD_주제.md`로 추가하고 기준 시간대를 적는다.
- 기존 문서를 덮어쓰거나 삭제하지 않는다. 같은 날짜·주제의 후속판은 `_v2`, `_v3`처럼 새 이름을 쓴다.
- 각 문서에 상태, 대상 버전, 변경한 규칙, 미결정 항목과 검수 범위를 명시한다.
- 승인된 변경은 승인 내용과 적용 범위를 요약한다. 비공개 대화 링크나 원문은 공개 문서에 넣지 않는다.
- 저장 후 짧은 변경 요약, 실제 커밋 링크와 파일 링크를 전달한다.
- 다른 Work에 인계할 때 이 기준 문서의 경로와 커밋 링크를 함께 제공한다. 문서가 올라왔다는 사실만으로 상대가 읽었다고 가정하지 않는다.
- 공개 저장소에는 개인정보, 인증 정보, API 키, 비공개 업무 자료를 넣지 않는다.

## 9. 다음 확인의 우선순위

현재 기준을 유지하면서 먼저 실제 브라우저와 휴대폰의 시작 → 영입 → 첫 중복 갈래 선택 → 보조 카드 선택 → 보스 → 결과 → 새 런 흐름을 확인한다. 최고 웨이브 기록과 새 런 초기화도 함께 확인한다.

그다음 동일한 조건으로 갈래별 처치·누수·소요 시간과 성장 시점을 비교한다. 현재의 여유 있는 수치는 실측을 바탕으로 조정한다. 신규 영웅과 카드 풀 확장은 이 검수 결과와 별도의 채택 결정을 바탕으로 진행한다.
