## 작업 결과

기존 인계의 자동 검증 주장을 실제 전달 ZIP의 새 격리 사본에서 QA가 재실행했다. 최신 사용자 제보 수정 범위인 화면 배율·입력 좌표·플랫폼 분리에 한정했다. 과거 v0.10 장판 전달물이나 전체 30 suite를 반복하지 않았다.

| 최종 실행 | 검사 | 실패 | 환경 |
|---|---:|---:|---|
| AndroidScale | 91 | 0 | Android Startup Fixture로 export-pack한 격리 PCK, android=true 확인 |
| AndroidScale | 91 | 0 | 원본 SOURCE desktop 분기, android=false |
| WebScale | 290 | 0 | 네이티브 Window에서 CSS 크기·DPR 1/2/3 입력 변환 |
| 합계 | 472 | 0 | 세 실행 모두 종료 코드 0 |

Android 검사 크기: 720×1600, 1080×2340, 2340×1080, 1080×1920, 1920×1080, 1440×3120, 800×1280. 각 크기에서 시작 배치·HUD 경계·물리 좌표 주입에 의한 셀2 배치·전투 시작 버튼·회전 후 논리 크기·일시정지 시간 보존을 확인했다. 1080×2340은 390×845, 1440×3120도 390×845로 배치됐다. WebScale은 8개 CSS 크기×3 DPR 조합이다.

터치/마우스는 엔진 입력 이벤트로 주입했다. 실제 손가락·Android OS·브라우저 실행이 아니다. 생성 PCK는 시험용이며 배포 APK/PCK와 같은 바이트라고 주장하지 않는다. 전달 APK 자체를 설치하거나 재검증하지 않았다.

초기 Android 시도는 SOURCE의 project 설정에 custom_features를 추가했으나 android=false로 실행됐다. 91개 PASS여도 Android 근거에서 제외했다. 이를 확인하고 원래 project 설정을 복원한 뒤 전달물에 이미 있는 Android Startup Fixture export preset으로 PCK를 생성하여 android=true인 최종 실행을 얻었다. 초기 로그도 보존했다. 게임 결함이 아닌 시험 환경 구성 문제다.

실행 후 원본 ZIP의 파일 318개를 전부 바이트 비교했고 변경 0개였다. 추가 import 캐시·QA 출력과 별도 PCK는 격리 경로에만 생성했다. 운영 파일 수정/배포 없음.

증거: Nightroad-QA-v14-Scale-2026-10-04.zip. 인수 해시, 원본 보존 비교, 초기/최종 로그, 요약 JSON, 재현 안내를 비공개 전달 경로에 저장했다. 공개 저장소에 비공개 게임 코드는 포함하지 않았다.

## 문제점과 남은 한계

검사 범위의 화면 좌표 결함은 재현되지 않았다. 검사 수는 assertions이며 실제 사용자 수나 플레이 횟수가 아니다. 실제 화면 렌더링·가독성·청취는 이번에 검사하지 않았다.

기존 비공개 Site 인증 차단의 해소 증거와 실제 Android 기기 접근이 없다. 로그인 요청을 반복하지 않았다. 최신 APK 업데이트, 기존 저장 보존, safe-area, 시스템 Back, 실제 touch, 발열/성능, 최종 Web WASM/IndexedDB 및 3–5명 검수는 미검증이다. 이번 PASS로 1차 인수표의 플랫폼/사람 문턱을 닫지 않는다.
