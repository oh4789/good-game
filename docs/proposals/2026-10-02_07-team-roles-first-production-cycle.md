## 1. 사용자 확정 사항

이번 채팅은 디펜스 기획팀을 담당하고, 다른 Work에 전달할 작업을 정리한다.
게임의 기존 확정 사항은 단일 진영, 최대 출전 3명, 3×3 내부 배치, 웨이브 사이 재배치, 사각 경로 완주 피해·퇴장, 자동 공격·수동 궁극기, 처치 자원 영입과 처치 기반 레벨업의 분리, 약 7분 런이다.
기획 담당은 게임 코드를 수정하거나 배포하지 않는다.
새 자료는 docs/proposals에 추가하며 기존 파일을 덮어쓰지 않는다.

## 2. 제안 및 이전 문서와 관계

아래 역할 구분과 작업 순서는 제작 운영 제안이다. 채팅방을 모두 새로 만들 필요는 없으며 한 Work가 둘 이상의 직무를 수행할 수 있다.
06의 Work 1 전투 설계는 이 기획팀이 담당할 수 있다. 별도 기획 Work가 이미 작성 중이면 그 문서를 검토하여 보완하고 같은 수치표를 중복 작성하지 않는다.
06의 Work 3 디자인은 아트·UI와 애니메이션·VFX 두 작업 묶음으로 분리한다. 담당자가 같아도 완료 상태는 따로 기록한다.
06의 Work 5 QA는 재현·기능 검수와 플레이 기록 분석을 구분한다.
기존 전투 규칙이나 수치를 변경하는 문서가 아니다. 톱니 공방·영웅 이름·10웨이브·241마리 등은 이전의 시험 제안 상태를 유지한다.

기획 변경은 '기존 규칙 / 새 제안 / 이유 / 영향 / 시험 방법'을 남긴다. 담당자가 다르다는 이유로 확정 사항을 바꾸지 않는다.

## 4. 첫 제작 주기의 목표 [제안]

각 단계의 완료는 실제 산출물과 검증으로 판단한다. 예상 작업 시간이나 처리 속도는 현재 알 수 없으므로 임의의 완료 날짜를 약속하지 않는다.

## 5. 생동감 개선 상세 명세 [제안]

### 기획 의도
사용자가 지적한 '캐릭터가 움직이지 않음', '무기와 유령이 잘림', '몬스터가 너무 빨리 사라짐'을 구분해서 해결한다.
움직임과 잘림은 에셋·렌더링 검수 대상이고, 빠른 처치는 HP·공격·생성 간격 실측 대상이다.

### 영웅 동작 계약
| 동작 | 화면에서 읽힐 변화 | 게임 판정과 관계 |
|---|---|---|
| 대기 | 작은 호흡·무기 흔들림 | 실제 배치 좌표·사거리 중심은 이동하지 않음 |
| 발사 | 포구 섬광·짧은 반동 | 개발의 발사 사건과 연결. 장식 동작이 추가 피해를 만들지 않음 |
| 장전 | 탄통·포신·손의 복귀 동작 | 실제 재장전이 없는 병종이면 공격 사이 회복 동작으로 명명 |
| 궁극기 | 기본 공격과 다른 강조 | 지속·충전은 로직 데이터 사용 |
| 강화 | 해당 장비 또는 효과 아이콘 변화 | 승급과 카드 강화를 서로 구별 |

비비처럼 빠른 연사는 매 탄환마다 전체 몸 애니메이션을 처음부터 재생하지 않는 방식을 우선 시험한다. 포구 섬광과 무기 반동을 몸 동작과 분리해 떨림을 줄인다.
탄코는 포신 반동, 로코는 발사관 반동·연기로 구분한다. 공격 속도가 바뀌어도 애니메이션 완료를 기다리느라 실제 공격 횟수가 달라지지 않아야 한다.

### 피격·사망·누수 구분
- 피격: 짧은 반응. 적이 아직 살아 있다는 것을 유지.
- 사망: 판정·표적·보상 처리는 즉시 1회 완료하고 장식 잔상만 짧게 남김. 05의 약 0.25초는 시험값.
- 누수: 퇴장과 공용 HP 피해 표현. 처치 보상·처치 효과음은 재사용하지 않음.
- 장갑 약화: 색 외에도 금간 장갑 또는 아이콘으로 표시.
- 보스 50% 전환: 장갑 상태 변화가 한 번만 발생. 무적 시간을 임의로 추가하지 않음.

### 잘림 검수
- 모든 프레임에서 무기·연기·탄통·효과가 의도하지 않게 프레임 경계에 닿는지 확인.
- 3×3 아홉 칸 전부에서 네 방향 공격과 화면 가장자리 표시를 검사.
- 스프라이트 캔버스 잘림과 UI/부모 영역 마스킹을 별도 원인으로 기록.
- 에셋별 크기·원점·포구 위치·프레임 순서·FPS·반복·종료 동작·효과 범위를 제출.
- 컨셉 그림만 있으면 '컨셉 완료 / 게임용 에셋 미완료'로 보고.

## 6. 기획팀의 다음 산출물 [제안]

우선순위는 다음과 같다.
1. 기본 3병종의 공격·사거리·표적·투사체 명세.
2. 기존 전용 카드 9종과 공용 예비 카드 상세표.
3. 궁극기 충전·지속·표적 소실·웨이브 종료 처리.
4. 초반 영입의 두 순서와 추천/비추천 배치 비교표.
5. 실측 후 적 체력·경제·시간 조정안.

기획팀은 결과를 기다리는 동안 구현 없이 계산 가능한 항목을 진행할 수 있다. 실제 소스를 모르면 기존 수치를 확인했다고 하지 않고 독립 시험값으로 표기한다.
스토리·진영 추가·영구 성장·마케팅은 이 첫 제작 주기의 완료 조건에 넣지 않는다.

## 8. 미결정 및 현재 상태

- 실제 개발 저장소·기준 빌드·엔진 규격: 이 작업에서 미확인.
- 각 직무를 어느 채팅 Work가 맡을지: 사용자의 기존 담당 배치에 연결 필요. 별도 새 채팅 개설은 필수 아님.
- 기획 수치 상세표의 기존 병행 작성 여부: 다음 작성 전 자료실에서 확인.
- 이번 문서: 작성 완료.
- 다른 Work 전달·수락, 코드 구현, 에셋/음원 제작, 실행 검수: 이 문서 작성으로 완료 처리하지 않음.

공통 보고 형식: 작업 ID / 상태(완료·진행 중·미완료·확인 필요) / 산출물·커밋 / 검증 증거 / 충돌·미결정 / 다음 인계.
