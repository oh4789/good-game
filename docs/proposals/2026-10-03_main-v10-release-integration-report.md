## 반영 범위와 판단

초반 적을 알아보기 전에 처치되는 현상을 검토한 뒤, 작은 화면 피드백 변경을 반영했다. 적이 살아 있는 시간이나 HP를 늘리는 변경은 하지 않았다. 이전의 넓은 HP 조정 후보는 추가 패배와 지나친 진행 시간 때문에 채택하지 않았으며 이번에 반복하지 않았다.

- 이미 처치된 적의 어둡고 납작한 형태가 일시정지하지 않은 실제 표시 시간 220ms 동안 더 납작해지며 사라진다. 배속과 독립적이다.
- 최대 12개를 유지하며 넘으면 가장 오래된 잔상부터 제거한다. 자연 진행에서 관측한 최대는 7개다.
- 전장 경계와 atlas UV에 맞춰 자르고 살아 있는 적·상태 표시보다 아래에 그린다. 잔상에는 그림자·HP·상태 표시를 붙이지 않는다.
- 모든 웨이브에 같은 처치 표현을 적용한다. 기존 파티클은 그대로 유지한다.
- 보상 뒤의 기존 처치 사건을 읽고 복사한 위치·종류·나이만 보관한다. 살아 있는 적의 상태를 보관하거나 모델을 고치거나 RNG를 호출하지 않는다.
- 수동 일시정지·상세/선택창에서 수명이 멈추고 배치 단계에서는 다시 흐른다. 실제 포커스 이탈·앱 중단은 단계와 관계없이 잔상을 지운다. 종료·새 런·이어하기의 화면 초기화도 지운다.
- 잔상은 저장하지 않는다. 기존 파티클은 정확히 복원하며, 이어하기가 새로운 처치 잔상을 만들지 않는다.

런타임 변경은 화면 스크립트 하나뿐이다. 나머지 런타임 스크립트·데이터·에셋·장면·폰트·프로젝트 설정·export preset은 v0.9와 바이트가 같다. 처치 시점·타깃·보상·웨이브 전환·저장 schema·HP·속도·영입·카드·경제·명단은 바꾸지 않았다. 1·2·3·5·10배속, 첫 영입부터 3영웅 각각 1/3과 첫 중복 승급은 그대로다.

네이티브 창 제목은 동결한 프로젝트 설정의 v0.9를 유지한다. 릴리스/아카이브 및 배포 wrapper 식별은 v0.10이다. 이전 버전의 고배속 저장 호환 한계는 v0.9에서 이어받으며 이번 변경으로 새 저장 호환 경계를 추가하지 않는다.

## 검증 결과와 근거의 범위

### 현재 규칙의 기준 재측정

현재 v0.9에서 네 가지 고정 정책·네 시드·전체 8갈래 조합으로 128런을 측정했다. 계측/비계측 상태·RNG 비교 116,604항목에서 차이가 없었다. 1웨이브의 모든 적은 첫 피해 뒤 시뮬레이션 1초 안에 처치됐으며 중앙값은 0.733초다. 1웨이브 단발 처치는 없었고 1~3웨이브의 84.07%가 1초 미만, 18.45%가 한 피해 사건으로 처치됐다.

이 제한된 정책 표본은 123/128승이며 만피 종료는 119건이다. 뒤쪽 배치·영입 지연 정책의 기존 패배를 포함한다. 일반 사용자 승률이나 난이도 평가가 아니다. 기존 처치 파티클 0.32 시뮬레이션 초는 10배속에서 실제 32ms이므로 짧게 형태를 남기는 표현을 검토했지만, 인지 개선을 입증한 것은 아니다.

### 최종 소스·정확한 PCK

최종 소스와 정확한 최종 PCK에서 각각 21개 검수 묶음이 통과했다. 상속 회귀 19개와 새 잔상 수명·128사례 전 화면 비교를 포함한다. 최종 포커스 보완 이전에 시작했던 소스 회귀 기록은 그대로 두고, 최종 코드에서 19개를 깨끗하게 다시 실행해 모두 exit 0임을 확인했다. 최종 PCK의 포커스/중단 추가 4사례도 통과했다.

- 전 화면 기준/후보 비교: 소스와 최종 PCK 각각 동일한 128사례, 각각 324,840항목. 매 표시 스텝 뒤 전체 모델·UI·RNG·저장 캡처가 바이트 단위로 같았다.
- 기준/후보 모두 123/128승. 기존 패배 5건, 최종 HP·결과·시뮬레이션 진행 시간도 변하지 않았다. 같은 사례의 소스/PCK 반복을 독립 자연 플레이 수로 더하지 않는다.
- 독립 검수: 16전체 런·실제 처치 5,520건에서 11,171항목 통과. 처치마다 정확히 한 잔상, 합성 30처치 때 상한, 219ms 존재/221ms 만료, 실제 저장 런 이어하기·포커스/중단 알림을 확인했다.
- 320/390px 경계·UV 조합 1,061,684건에서 전장과 atlas 범위 이탈이 없었다.
- 빈 프로젝트 경로의 compiled-resource 검수 157항목: 런타임 스크립트 16개 인스턴스화, 음원 31개 디코딩과 루트 장면·폰트·영웅 바인딩 확인. 청취 합격을 의미하지 않는다.

### 네이티브 화면 비교

소스와 정확한 PCK의 비교 이미지 20개가 바이트 단위로 같았다. 각 이미지는 왼쪽 v0.9, 오른쪽 후보를 보여 주며 320/390px·1/10배속과 후반 7웨이브 10배속을 포함한다. 두리는 네이티브 이미지를 직접 보고 납작한 처치 표시가 구분 가능하되 미묘한 효과임을 확인했다. 초기 관찰 구간의 최대 잔상은 2개, 독립 전체 10배속 런에서는 7개였다. 스크립트로 만든 네이티브 렌더링 검수이며 사람의 플레이·실제 휴대폰 가독성 증거가 아니다.

### 실패·수정·재실행 기록

초기 수명 테스트의 불완전한 합성 보상 상태로 스크립트 오류가 발생했다. 유효한 선택지를 공급하도록 시험 도구를 고치고 다시 실행했다. 초기 결과는 합격 근거로 쓰지 않는다. 독립 검수에서 v0.9의 배치 단계는 포커스 일시정지를 설정하지 않는 점을 발견했고, 모델 정지 규칙을 넓히지 않고 실제 포커스 이탈 시 잔상만 지우도록 보완했다. 실제 알림과 기준 상태 일치로 재검증했다.

PCK의 추가 128런 비교는 기존 360초 시험 제한에서 80사례를 마친 뒤 시간 초과했다. 그때까지 단언 실패는 없었으며 원본 기록을 보존했다. 같은 PCK를 변경하지 않고 1,200초 제한으로 다시 실행해 128사례를 완료했다. 동시 실행 환경의 소요 시간은 실시간 성능 벤치마크로 해석하지 않는다.

초반 적의 실제 생존 시간과 난이도 결과는 그대로다. 처치 잔상이 살아 있는 적과 혼동되지 않는지, 작은 휴대폰에서 인지에 도움이 되는지는 실제 플레이 피드백이 필요하다.
