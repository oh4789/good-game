## 2. 실제로 발견한 충돌
07 화면 명세는 카드/정지 시 BGM 감쇠를 제안한다.
음향 v4는 카드 감쇠, 수동 정지의 위치 보존 정지를 권장하며 미결정으로 표시한다.
이번 보완 후보: 카드/준비에서는 음악을 낮춰 유지하고, 수동 정지/앱 숨김에서는 위치를 보존해 멈춘다.
개발1팀이 채택 여부를 기록하기 전에는 기존 구현을 일방적으로 바꾸지 않는다.

## 3. 상태별 동작표 [제안]
| 유효 상태 | 전투·충전 시간 | 허용 조작 | BGM | 전투 SFX |
|---|---|---|---|---|
| 초기/웨이브 준비 | 정지 | 배치·영입·정보·시작 | 기본 gain보다 -6dB | 신규 재생 없음 |
| 전투 | 진행 | 영입·유효 궁극기·정지 | 기본 gain | 확정 사건만 |
| 카드 선택 | 정지 | 카드 설명·선택·시스템 정지 | 기본 gain보다 -6dB | 신규 재생 없음 |
| 수동 정지 | 정지 | 설정·재개·종료 확인 | 위치 보존 정지 | 정지/해제 |
| 앱 숨김 | 정지 | 없음 | 위치 보존 정지 | 정지/해제 |
| 결과 | 정지 | 상세 기록·새 런·메뉴 | 300ms 종료 후보 | 승패 UI음 1회 |

UI 확인음은 전투 SFX와 구분하며 수동 정지의 설정 조작에서 허용한다.
보스곡 기본 gain 보정과 카드 감쇠는 별도 층이다. 상태가 바뀔 때마다 -6dB를 누적하지 않는다.
음소거 해제는 현재 상태 정책을 따르며 정지 중 음악을 강제로 시작하지 않는다.
오디오 장치가 잠겼거나 파일을 못 읽어도 게임 상태·카드 선택을 막지 않는다.

## 4. 중첩 상태 처리 [제안]
상태 하나를 임의로 덮어쓰는 방식 대신 전투/준비의 기반 상태와 카드·수동정지·앱숨김 사유를 보존한다. 엔진별 구현 방식은 개발1팀이 결정한다.
- 카드 중 정지 → 재개하면 같은 후보 카드. 카드를 다시 추첨하지 않는다.
- 카드 중 앱 숨김 → 복귀 재개 안내 → 명시적 재개 → 같은 카드. 뒤의 전투는 계속 정지.
- 수동 정지 중 앱 숨김 → 복귀 후에도 수동 정지를 유지.
- 전투 중 앱 숨김 → 복귀만으로 전투 재개 금지.
- 재개 버튼은 다른 정지 사유를 무조건 지우지 않는다.
- 결과는 카드·준비보다 우선한다. 확정 결과 뒤 대기 카드 UI를 열지 않는다.
- 복귀 시 보류 사격음·과거 누수음·음악 전환을 한꺼번에 재생하지 않는다.
- 정지 메뉴 위의 종료 확인을 취소하면 정지 메뉴로 돌아간다.

시간 집계는 각 순간을 전투/준비/카드/정지 중 하나에만 넣는다.
수동정지 또는 앱숨김이 있으면 정지 시간으로 분류한다. 그 외 카드가 있으면 카드 시간, 그 외 기반 상태 시간이다.
결과 이후 시간은 런 플레이 시간에서 제외한다.

## 5. 1팀과 2팀의 경계 [제안]
| 항목 | 개발1팀 | 개발2팀 |
|---|---|---|
| HP·XP·고철·별·카드·충전 | 상태 확정·검증 | 받은 값 표시 |
| 영입·궁극기·카드 입력 | 유효성 확인·처리·거절 사유 반환 | 의도 전달·피드백 |
| 웨이브/보스/승패 | 판정·사건 발행 | 예고·BGM·결과 연결 |
| 배치 | 준비 상태와 유효칸 검증 | 선택·드래그·범위 미리보기 |
| 오디오/애니메이션 | 판정 시점 전달 | 재생·동시음·화면 표현 |
| 모바일 | 논리 좌표·조작 계약 | 안전영역·버튼·잘림·패널 |
| 최종 병합 | 통합 및 회귀 확인 | 변경 범위·증거 인계 |

애니메이션 종료를 기다려 피해·보상·다음 웨이브를 확정하지 않는다.
2팀 UI가 표시한 고철을 독립 차감하거나 궁극기 충전을 자체 초기화하지 않는다.
공유 파일 변경은 파일 소유·수정 구간을 먼저 조율한다. 실제 경로가 없으므로 가상의 파일명을 작업 범위로 지정하지 않는다.

## 6. 최소 연결 항목 [제안]
전달 형식은 기존 구조를 우선한다. 아래는 필요한 의미이며 새 프레임워크 도입 요구가 아니다.

공통 식별: runId, 단조 증가 stateRevision, 일회성 eventId, 입력 commandId.
- 상태 스냅샷: 기반 상태/정지 사유, 웨이브, HP, XP, 고철, 영웅/카드/충전, 현재 카드세션, 확정 결과.
- 영입 응답: 성공 여부, 영웅ID, 신규/중복/승급/최대성환급 결과, 확정 잔액.
- 카드 제시: sessionId와 3개 유효 cardId. 선택은 sessionId+cardId로 검증.
- 궁극기 응답: 승인 또는 거절 사유. 클릭 자체는 발동 사건이 아니다.
- 보스 조우: 실제 조우 확정 사건. 화면 렌더 횟수나 벽시계로 음악 전환 금지.
- 런 종료: victory/defeat/abandoned 및 확정 결과 기록. 보스 사망과 분리.

동일 commandId 재수신은 중복 실행하지 않는다. 다른 commandId의 연속 영입은 매번 현재 자원과 상태를 검증한다.
다른 runId의 늦은 콜백은 무시한다. 이전 stateRevision으로 화면 값을 되돌리지 않는다.
음향·연출은 같은 eventId를 한 번만 소비한다. 늦게 화면을 연결할 때 과거 사건을 재생하지 않고 현재 상태를 표시한다.
대량 누수음이 하나로 합쳐져도 피해 집계는 원래 사건 전체를 사용한다.

## 8. 팀별 다음 작업 요청
개발1팀: 실제 코드 위치/기준 커밋/실행법을 기록하고, 기존 상태·명령·사건과 위 의미의 대응표를 작성한다. 채택한 정지 정책과 소유 파일 범위를 명시한다.
개발2팀: 대응표를 받아 메뉴/HUD/선택/결과·모바일 표현을 별도 브랜치에서 연결한다. 화면 잘림·무기 범위·44픽셀 조작 영역을 확인한다. 전투 규칙 변경은 1팀과 조율한다.
음향팀: BGM 2곡과 효과음31개의 실제 접근 가능한 패키지·manifest를 전달하고, 수동정지 위치 보존·카드 감쇠·보스 전환을 적용 빌드에서 청취한다.
QA팀: 같은 소스 커밋으로 INT-01~10을 수행하고 통과/실패/미검수를 분리한다.
기획팀: 실제 실패와 채택 차이를 보고 기존 문서의 필요한 부분만 보완한다.

이 문서는 인계용 요청을 저장한 것이며 다른 Work에 직접 메시지를 보냈거나 작업 착수를 확인한 보고가 아니다.
