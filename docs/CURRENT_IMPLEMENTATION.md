## 같은 사용자의 소스 전달물

기존 SOURCE·WEB 항목을 갱신하고 이전 이력을 보존했다. 아래 최종 영수증의 파일명·크기·해시로 승인된 같은 사용자 Library 또는 첨부의 실제 파일을 대조한다.

이 공개 저장소는 문서 자료실이다. 비공개 소스·에셋을 자동 업로드하지 않는다. 도구나 파일 접근이 없으면 현재 파일명·버전을 지정해 필요한 첨부를 요청하고 차단으로 기록한다. 비공개 실행·Library 링크·ID는 공개 문서에 넣지 않는다.

## 현재 기능과 역사적 기록의 구분

- v0.9는 1·2·3·5·10배속과 첫 영입부터 3영웅 각각 1/3 무작위 뽑기를 적용했다. 처음 두 번 미보유 영웅 보장은 폐지됐다. 첫 중복 즉시 승급·2갈래 선택과 이후 중복 성장은 유지한다. [v0.9 확정 보충](proposals/2026-10-03_v09-canonical-speed-recruitment-addendum.md)이 이전 보장 규칙을 명시적으로 대체한다.
- 기존 결과·RNG 상태·열린 선택창은 그대로 복원하며 다시 뽑지 않는다. 기존 런의 향후 영입도 새 전체 명단 규칙을 사용한다. 가격 12·12·24·이후 +6, XP·고철·스폰 타이밍·명단·카드 수치는 변경하지 않았다.
- 60Hz 고정 스텝을 유지하며 250ms 실제 시간 제한 후 배속을 적용한다. 모달·종료는 즉시 멈추고 선택 후 밀린 시간을 몰아서 처리하지 않는다.
- v0.8의 새 런은 1~9웨이브 스폰 구간을 28초에서 32초로 늘리고 10웨이브는 28초를 유지한다. 기존 런은 남은 런 전체에서 이전 28초 타이밍을 유지한다. 전투 중·선택창 복원과 백업 복구에도 같은 런 규칙을 적용한다.
- 적 수·HP·경제·영웅·카드 수치는 그대로다. 기존 표준 정책 시뮬레이션의 빈 대기 중앙값 약 89→57초는 제한된 관측이며, 적 조기 소멸 문제나 사람의 재미·난이도를 해결했다는 뜻은 아니다.
- v0.7은 3영웅 텍스처의 import 크기 제한과 축별 UV 보정을 통합했다. 원본 PNG·메시·메타데이터·발/총구 기준점은 보존했으며 런타임 소스 변경은 4개 파일에 한정된다.
- v0.7 당시 PCK는 v0.6 대비 4,007,088 bytes, 38.46% 작아졌다. 세 영웅의 디코딩된 mip 이미지 할당량은 25,154,992 → 3,959,012 bytes로 84.26% 감소했다. 전체 GPU·프로세스 메모리 절감률, FPS 개선률 또는 휴대폰 성능 보장이 아니다.
- v0.6의 적 HP·장갑·보스 전면 표시, 출입구 가독성, 실제 HP 손실량 기반 누수 피드백과 마지막 적 누수 뒤 웨이브 전환 보호를 유지한다.
- v0.5의 비비·탄코·로코 원화, 발사 사건 기반 단일 스프라이트 메시 모션, 전장 안으로 자른 배치 사거리와 전면 승급 배지를 유지한다. 완전한 관절 리그는 아니다.
- v0.4의 같은 런 이어하기·저장 schema·백업 복구·손상 보존·새 런 확인/취소 보호를 유지한다. 기존 런을 강제로 초기화하지 않는다.
- 효과음·BGM, 반응형·터치·동작 줄이기, DPR·포인터 대응을 보존한다. 신규 음향 설정 기본값은 OFF다.
- v0.1·v0.2·v0.3·v0.3.1·v0.4·v0.5·v0.6·v0.7·v0.8의 아홉 런타임 버전과 기존 저장 브리지를 보존했다. 엔진과 저장 경로는 바꾸지 않았다.
- [v0.3 게임 규칙](proposals/2026-10-03_v03-canonical-decisions.md)의 영웅·중복·갈래·카드·경제 방향을 유지한다. 초기 미보유 보장은 v0.9 보충으로 대체됐다. 과거 보고의 미배포·계획 문구는 당시 상태이며, 현재 구현은 이 문서와 [v0.9 보고](proposals/2026-10-03_main-v09-release-integration-report.md)를 따른다.

## 이어하기와 이전 버전 주의

현재 런은 v0.9에서 이어한다. 2배를 넘는 저장 속도는 이전 클라이언트가 읽지 못할 수 있다. v0.8 전환 때부터의 아래 이전 클라이언트 복구 경계도 여전히 주의한다. 기존 런은 기존 타이밍으로 이어진다. v0.7을 단순히 여는 것은 읽기 전용이며 저장을 변경하지 않는다. 다만 새 런 전환이 중단되어 새 저장과 이전 호환 저장이 함께 남으면 v0.7의 복구는 더 이른 진행을 제시할 수 있다. 이를 명시적으로 이어하면 활성 저장이 옛 진행으로 교체될 수 있고, 먼저 보존된 새 저장 바이트가 자동으로 돌아오지는 않는다. 정상 완료된 새 v0.8 런은 v0.7에서 이어하기가 비활성화된다.

## 검수 경계와 다음 인수

v0.9 소스와 정확한 최종 PCK 각각 19개 검수 묶음이 모두 exit 0으로 통과했다. 독립 검수 46,348항목, 전체 상태/RNG 일치 350사례, 첫 뽑기 6,000시드 표본, 120×30회 영입, 실제 v0.8 저장 10개 복원, 속도 UI 159항목과 거래·음향·스폰 회귀 11,865항목을 포함한다. 자세한 수와 한계는 v0.9 보고를 따른다. 같은 사례의 반복 검증을 서로 다른 자연 플레이로 합산하지 않는다.

정확한 PCK의 네이티브 검수는 시드 1·고철 12를 주입하고 비비만 가진 fixture로 수행했다. 첫 영입 중복의 2갈래 선택, 비비 +1과 다른 영웅 잠금 유지, 10배속 버튼, 종료·재실행·이어하기 복원을 확인했다. 자연 경제 진행·휴대폰 검수가 아니다. 과거 QA는 이력으로 보존하며 이번 재실행과 구분한다.

**v0.9 브라우저 WASM·IndexedDB·실제 휴대폰·주관적 믹스는 미검증이다.** 승인된 실행 접근·기기 증거가 없는 항목은 차단/미검증 상태다. 배포 성공·네이티브 PASS·백업 바이트 일치를 웹/휴대폰 합격으로 바꾸어 쓰지 않는다. Android APK·PWA·safe-area·발열·배터리·장시간 성능도 미검증이다.
