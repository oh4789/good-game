## 2. 결정과 제안의 의미

- **[결정]**: 대화에서 사용자가 명시한 방향. 이 자료가 기존 구현의 완료 상태를 의미하지는 않는다.
- **[제안]**: 설계 보조가 제시한 컨셉·운영안·시험 수치. 실제 게임에 맞춰 조정할 수 있다.
- **[확인 필요]**: 현 게임 구조를 보거나 사용자 선택이 있어야 확정할 항목.
- 최신 날짜라는 이유만으로 제안을 결정으로 바꾸지 않는다. 반영한 결정과 시험 채택한 제안을 각각 기록한다.

## 3. 최신 방향의 핵심

경험치 레벨업은 강화 카드 선택에 사용하고, 적 처치로 얻는 별도 자원은 영웅 뽑기에 사용한다. 영입은 강화 카드에서 분리한다. 한 런에서는 한 진영만 사용한다.

과거의 혼합 진영 파티, 레벨업 카드로 새 영웅 영입, 런 밖 해금 뽑기는 현재 방향과 충돌하는 경우 적용하지 않는다. 영구 영웅 수집 여부 자체는 미확정이다.

## 4. 현재 확인한 범위

작성 시점 자료실의 main 브랜치는 README.md만 있는 초기 상태였다. 게임 소스·실행 빌드는 이 저장소에서 확인하지 못했다. 따라서 이 자료는 기획 검토와 개발팀 전달용이며, 기존 게임 기능을 확인하거나 밸런스를 실측한 보고서가 아니다.

기준 커밋: [초기 자료실 상태](https://github.com/oh4789/good-game/commit/0b31479eb455b4c7aa71f40a419f43092be20af0)

## 5. 개발 담당에게 전달할 요청

> 이 폴더의 결정 사항을 먼저 읽고 현재 게임과 비교해줘. 제안은 호환되는 작은 단위부터 시험 채택하고, 적용한 항목·수정한 수치·검수 결과를 기록해줘. 영입 뽑기와 레벨업 강화를 분리하고, 한 런의 진영이 섞이지 않게 해줘. 실행하지 않은 항목은 미검수로 표시해줘.

실제 개발 소스가 다른 저장소에 있다면 그 소스에 변경을 적용한다. 이 good-game 저장소는 자료실로 사용하며 이 문서 추가가 게임 배포를 뜻하지 않는다.

## 6. 이후 자료 저장 규칙 [결정]

- docs/proposals/ 아래에 Markdown 파일로 저장한다.
- 파일명은 YYYY-MM-DD_주제.md 형식으로 만든다. 날짜는 작성자의 기준 시간대를 기록한다.
- 기존 파일은 덮어쓰지 않는다. 같은 날짜·주제의 후속 문서는 _v2, _v3처럼 새 이름으로 추가한다.
- 문서에는 결정·제안·확인 필요, 작성 범위와 검수 여부를 표시한다.
- 저장 후 커밋 링크와 추가한 파일 목록을 전달한다.
- 공개 자료에는 개인정보·API 키·인증 토큰·비공개 업무 자료를 넣지 않는다.
- 다른 작업이 읽을 때는 문서 경로와 커밋 링크를 함께 전달한다. 별도 대화가 문서를 읽었다고 자동으로 가정하지 않는다.
