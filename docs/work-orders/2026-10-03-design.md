## 먼저 확인할 전달 문제

이전 전달에서는 링크를 열어도 글자만 보이거나 링크 자체가 보이지 않는 문제가 있었다. 이번 인계는 사용자가 실제로 볼 수 있는 결과가 필수다.

- 동작 검토에는 MP4, GIF 또는 서비스가 표시하는 이미지·영상 첨부를 제공하고, 원본·파츠 파일을 별도로 인계한다.
- HTML 소스나 실행 여부가 확인되지 않은 링크만 전달하고 완료로 처리하지 않는다.
- 첨부 또는 미리보기를 직접 열어 실제 프레임이 보이는지 확인한다. 문법 검사만으로 리그나 애니메이션이 검증됐다고 하지 않는다.
- 기존 3영웅 HTML의 포즈·변형 수는 실제 리그와 자연스러운 동작의 검수 증거가 아니다.
- 이미 별도로 전달된 비비 MP4를 그대로 다시 만드는 대신 기존 데모의 확인 결과와 필요한 개선만 이어간다.
- 도구가 영상 변환이나 첨부를 지원하지 않으면 막힌 단계와 가능한 최소 대안을 보고한다. 열리지 않는 링크를 전달 성공으로 표시하지 않는다.

## DS-01 실제 에셋 인수와 비비 정리

우선순위 1 / 상태 PENDING

먼저 [기존 3영웅 원화](../proposals/2026-10-02_design-team-character-sources-v2.md), 동작 연구와 애니메이션 검토 자료를 읽고 자기 작업 환경의 실제 파일을 확인한다. 문서의 제작 완료 보고와 실제 파일 인수를 구분한다.

할 일:
1. 3영웅 원화와 비비 컷아웃 동작 데모의 실제 파일을 찾고 직접 이미지를 연다. 접근할 수 없는 파일은 이름만 추측해서 대체하지 말고 요청한다.
2. 기존 비비 원화·데모를 재사용할 부분과 보완할 부분을 정리한다. 이유 없이 전체 영웅을 다시 그리지 않는다.
3. 알파 가장자리, 빛 번짐, 무기 잘림, 발 기준점, 프레임 간 크기·위치를 확인하고 비비의 깨끗한 스프라이트 또는 몸·무기·섬광 분리 파츠를 준비한다.
4. 대기와 공격 동작을 프레임 또는 리그 미리보기로 보여준다. 피격 반응을 만들 경우 표현 검토용으로 표시하고, 영웅 개인 HP나 새 피격 규칙을 추가하지 않는다.
5. 현재 게임의 실제 입력 규격을 두리에게 확인한다. 기존 128/256 픽셀 제안을 확정값으로 간주하지 않는다. 확인 전에도 원본 보존과 파츠 정리는 진행할 수 있다.
6. 직접 픽셀과 재생 결과를 확인한다. 생성 이미지 한 장을 연속 애니메이션 검수 완료로 보고하지 않는다.

산출물:
- 실제 사용 파일 또는 승인된 전달 경로의 파일 묶음
- 직접 열어 확인한 MP4/GIF 또는 지원되는 이미지·영상 첨부 미리보기와 원본·파츠
- 파일별 manifest: 이름, 용도, 크기, 알파, pivot 좌표·단위, 포구 위치, 프레임 순서·시간, 반복 여부, 종료 상태, SHA256, 출처와 사용 조건
- 새 결과 문서: `design_DS-01_bibi-integration-handoff`

완료 증거:
- 비비의 원본과 파생 파일을 구분했고 이미지·재생을 직접 확인했다.
- 몸·무기 경계가 잘리지 않고 기준점이 흔들리지 않는다.
- 실제 파일을 두리의 승인된 인계 경로로 전달하고, 사용자가 볼 수 있는 첨부·미리보기가 열리는지 확인했다. 파일이나 볼 수 있는 증거가 없으면 DONE이 아니다.
- 게임 미통합 상태라면 명시한다. 기존 비비 데모도 현재 게임에 통합됐다고 표현하지 않는다.

## DS-02 탄코와 로코 통합용 파일 정리

우선순위 2 / 상태 PENDING / DS-01의 파일 계약 확인 후

- 같은 파일 계약으로 탄코와 로코의 깨끗한 원화, 필요한 파츠, 대기·공격 동작과 검토용 반응 동작을 정리한다.
- 탄코의 기존 원화 좌측, 로코의 하단처럼 경계에 닿는 부분을 실제 픽셀로 확인한다.
- 탄코 폭발/소이, 로코 유도/관통의 구분은 실제 구현과 맞는 색·무기·효과 표식으로 제안한다. 새 게임 판정은 만들지 않는다.
- 비비를 포함한 3영웅의 크기, 발 기준점, 시선·조준 방향과 여백을 맞춘다.
- 지원하는 방향과 크기에서 미리보기를 확인한다. 모든 9칸·8방향을 검사하지 않았다면 그 범위를 통과로 표시하지 않는다.

완료 증거:
- 탄코와 로코의 실제 파일·manifest·미리보기와 직접 확인 기록이 있다.
- 확인한 크기·방향·예외를 명시한다.
- 두리가 받아 연결할 수 있는 인계 상태이며, 통합과 휴대폰 실기 검수는 별도로 남긴다.

## 공개와 작업 경계

현재 요청은 게임 디자인 자료 제작과 정리다. 바이너리를 공개 GitHub에 올릴 때는 해당 자료의 공개 승인과 사용 권리를 확인한다. 불분명하면 파일명·해시·검수 상태만 공개 문서에 남기고 실제 파일은 승인된 전달 경로로 인계한다. 비공개 채팅·파일 접근 링크를 공개 문서에 넣지 않는다.

새 날짜별 design 결과 문서만 추가한다. 기존 원화·다른 팀 문서·게임 코드는 덮어쓰지 않는다. 새 영웅과 전체 재디자인을 자동으로 시작하지 않는다. 작업 ID별 완료 조건을 만족하면 끝내고 다음 지시를 기다린다.
