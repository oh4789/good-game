배포 소스는 원격을 새로 열어 확인했다. 배포 서비스는 성공을 보고했고 로컬 WEB 페이로드 멤버는 manifest와 일치했다. 서버의 보존 tar와 로컬 압축/해제 tar는 컨테이너 표현이 다르며 서버 tar 자체를 다시 내려받아 바이트 동일성을 검증하지는 않았다. 이를 Library SOURCE·WEB 실제 바이트 재조회 성공과 혼동하지 않는다.

이 공개 저장소에는 문서만 추가한다. 게임 소스·패치·에셋·ZIP 및 비공개 실행/Library 링크·ID, 개인·인증 자료는 공개하지 않는다. 파일 인수는 승인된 같은 사용자 전달 경로를 이용한다.

## 반영 범위

- 새 런: 1~9웨이브의 스폰 구간을 28초에서 32초로 늘렸다. 10웨이브는 28초다.
- 기존 런: 남은 런 전체에서 기존 28초 타이밍을 보존한다. 전투 중·보상/승급 선택창 복원, 단계별 저장과 백업 복구에도 같은 규칙을 사용한다.
- 적 수·HP·경제·영웅·카드 수치와 스폰의 난수 소비는 변경하지 않았다.
- 변경 런타임 파일은 SquareModel, RunState, SquareScreen의 도움말 버전 제목, project.godot의 창 제목으로 제한했다.
- Store·Data·저장 namespace/경로·기타 화면 동작·아트·음향·폰트·셰이더는 그대로다. v0.7의 텍스처 최적화와 v0.4 이후 저장 보호를 유지한다.
- [v0.3 확정 규칙](2026-10-03_v03-canonical-decisions.md)의 3영웅·6갈래·자동 전투·첫 중복 즉시 승급·이후 중복 성장·런 한정 보유 방향을 유지한다.

표준 정책 프로토타입 시뮬레이션에서 빈 대기 중앙값 약 89→57초, 표준 런 약 405초가 관측됐다. 이는 제한된 비교 결과이며 사람의 플레이 시간·승률·재미로 재측정한 값이 아니다. 타이밍 조정은 빈 대기를 부분적으로 줄이며 적 조기 소멸이나 초반 적 생존 시간을 해결하지 않는다.

## 소스·정확한 PCK·네이티브 검수

제작 검수 기록의 “미배포 후보”는 배포 이전 시점의 상태다. 이후 위 정확한 소스·PCK로 배포·백업을 확인했다. 이 문서 작성은 기존 검수 증거를 연결한 것이며 아래 게임 시험을 다시 실행했다는 뜻은 아니다.

- PacingCompatibility: 기존 타이밍의 자연 완료 8런을 실제 v0.7의 모델·화면·난수 바이트와 비교했다. 반복 중간 복원·보상/승급 모달을 포함한다. 새 규칙 8갈래 완료 런의 연속/복원 상태, 10웨이브 전체 스폰 간격, 난수 소비 불변, 새 런 초기화와 잘못된 규칙 식별자 9종을 확인했다. 소스와 정확한 PCK에서 1,523개 항목 통과다. 정해진 정책/seed의 승리를 사람의 승률로 집계하지 않는다.
- ResumeUI와 LegacyResumeUI: 소스·정확한 PCK에서 각각 224개 항목 통과. 선택/속도, 수동·포커스 일시정지, 카드·경험치·갈래·영입 모달 복원, 재추첨/중복 환급 방지, 준비 배치, 복원 진입과 쓰기 실패 재시도를 포함한다.
- StoreTests 34개 항목: journal 중단·오래된 writer·백업·손상 읽기 전용 처리·원본 보존·미지 schema·전체 원자적 복원 확인. 고의로 잘못 만든 JSON의 파서 오류는 시험 입력에 따른 예상 로그다.
- NewRunLongevity: 명시적 새 런 100회·화면 재생성 30회, 522개 항목 통과. 서로 다른 프로세스의 NewRunRestart 저장/읽기 해시 일치. 첫 실수로 쓰기 fixture 없이 읽기만 실행한 시도는 시간 초과였고 올바른 두 프로세스 순서로 다시 통과했다.
- UIFlows·AudioResumeTests·FeedbackLifecycle·FrameRates·RouteFrameRates와 AudioExtensionTests 통과. AudioTests 616개 항목은 소스·정확한 PCK에서 통과했다. 과거 무음 비교는 기존 타이밍을 명시하고 누락된 규칙 식별자만 정규화했다. 초기 실패는 비교 fixture 불일치였고 런타임 수정을 뜻하지 않는다.
- 독립 호환 검수 24,173개 항목 통과. 단계별 저장·백업 복구, 잘못된 규칙 식별자와 모든 웨이브를 확인했다. 이 시험은 스케줄을 분리하기 위해 적을 제거하므로 자연 전투 밸런스 증거가 아니다.
- 깨끗한 import/재수출로 컴파일 스크립트 16개, 로드 리소스 39개, 설정과 장면 의미를 대조했다. 의도한 스크립트 3개와 프로젝트 제목만 컴파일 데이터에서 달라졌으며 로드된 아트·음향·폰트·셰이더는 v0.7과 같다. export 캐시 메타데이터 차이를 전체 PCK 바이트 동일성으로 표현하지 않는다.
- 최종 PCK 네이티브 장면·모델 스모크 126개 항목 통과. 실제 화면에서 v0.8 제목, 기존 저장 진입→0.2초 일시정지 전투 이어하기, 도움말 v0.8 및 닫기/음향/확인 조작, 새 런 취소와 명시적 확인→새 배치를 확인했다. 읽기 전용 저장 검사에서 기존 규칙 유지와 새 런 규칙 전환을 확인했다.

## 이전 버전 이어하기 주의

새 v0.8 런은 현재 v0.8에서 이어한다. 기존 런은 기존 타이밍으로 계속된다.

원본 v0.7 Store를 사용해 정상 저장, 새 런 단계 저장 직후, 백업 처리 직후 상태를 확인했다. v0.7을 단순히 여는 것은 읽기 전용이며 보존·회전·승격·삭제하지 않는다. 정상 완료된 v0.8 새 런은 기본/백업 모두 새 규칙 태그를 가지므로 v0.7에서 이어하기가 비활성화된다.

새 런 전환이 중단되어 최신 새 규칙 저장과 이전 호환 저장이 함께 남으면 v0.7은 복구 경고와 함께 더 이른 기존 진행을 제시할 수 있다. 같은 상태에서 v0.8은 최신 새 규칙 저장을 선택한다. v0.7에서 옛 진행을 명시적으로 이어하면 활성 저장이 옛 진행으로 바뀔 수 있다. 호환되지 않는 새 바이트는 먼저 내용 해시로 보존되지만 그 보존본이 자동으로 활성 저장에 복원되지는 않는다. 새 v0.8 진행을 위해 v0.7 복구를 사용하지 않는다. 이는 기존 v0.7 동작이며 이번 릴리스에서 Store를 바꾼 결과가 아니다.

## 미검증과 다음 우선순위

- 브라우저 WASM 실행·IndexedDB·브라우저 강제 종료 시 저장 내구성은 미검증이다.
- 실제 휴대폰 터치·표시·safe-area·PWA·APK·GPU·발열·배터리·장시간 성능은 미검증이다.
- 주관적 음향 믹스·사람의 재미·난이도는 인증하지 않았다.
- 승인된 실행 접근·실기 증거가 없는 브라우저/휴대폰 검수는 현재 차단 상태로 유지한다. 네이티브 PASS·배포 성공·아카이브 검수를 실제 웹/휴대폰 합격으로 옮겨 적지 않는다.

1. QA: 정확한 v0.8의 브라우저 시작→전투→저장·재접속→이어하기와 새 런 확인/취소, 휴대폰 터치·표시를 우선 검증한다. 승인된 접근과 기기가 필요하며 OS·브라우저·버전·재현 증거를 남긴다.
2. 사용자 플레이 피드백: 초반 적 인식 시간, 빈 대기, 카드·영입 선택의 의미를 실제 경험으로 확인한다. 기존 자동화 208런 연구를 사람의 승률로 쓰지 않는다.
3. 기획·디자인: 초반 적 가시성, 카드와 영입의 범위를 좁힌 비교 제안을 준비한다. 적 HP·카드 수치·무작위 중복 보장 변경은 제안이며 현재 구현·승인으로 선언하지 않는다. 새 대형 기능보다 검수와 피드백을 우선한다.

운영 파일은 담당·기준 커밋·격리 변경·인수 조건을 확인한 뒤 작업한다. 기존 보고·규칙·팀별 결과는 보존하며, 이 보고는 현재 릴리스 상태만 갱신한다.
