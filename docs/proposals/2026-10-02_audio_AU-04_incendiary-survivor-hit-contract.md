## 연결 조건 — 의미 계약 제안
아래 이름과 필드는 실제 API 존재를 주장하지 않는다. 두리가 현재 연결 지점과 대응을 확인한다.

### 점화
- 실제 소이 장판 생성이 확정된 사건에서 1회 후보를 만든다. 발사, 매 프레임 표시, 장판의 주기 피해에서는 만들지 않는다.
- 장판 생성 사건의 고유 키를 런 식별자와 함께 소비한다. 같은 사건 재조회·재렌더는 0회다.
- 짧은 시간 여러 장판 생성은 sound ID 전체의 120 ms 간격과 최대 2 voice로 제한한다. 초과 사건은 버리고 나중에 몰아 재생하지 않는다.
- 기존 대포 착탄은 착탄당 1회 유지하며 점화는 소이 층을 추가한다. 피해 대상 수로 점화·착탄 횟수를 늘리지 않는다.

### 공용 연소 루프
- 현재 런의 살아 있는 소이 장판 수가 양수이고 전투가 진행 가능하며 소리 ON일 때만 공용 루프 1개를 허용한다. 장판 수에 따라 음량이나 voice를 더하지 않는다.
- 조건이 거짓→참일 때 0초부터 시작하고, 계속 참이면 재시작하지 않는다. 장판 A가 사라지고 B가 남아 있으면 계속 유지한다.
- 장판이 0개가 되거나 준비·카드·갈래 선택·수동 정지·포커스 정지·상세창 정지·소리 OFF로 전환되면 루프를 중지한다. 복귀 시 모든 정지 사유가 해소됐는지 확인하고 현재 장판 상태만으로 재평가한다.
- 복귀 시 루프 재시작은 허용하되 점화는 재생하지 않는다. 선택 중 전투 장판이 보존돼도 소리는 멈춘다.
- 결과·새 런·화면 해제에서는 플레이어와 예약 콜백을 정리한다. 이전 런 콜백은 새 런의 루프를 시작하거나 끌 수 없다.
- 일반 시작·종료는 30 ms fade를 시험 제안한다. 소리 OFF·화면 해제는 즉시 정지하며, fade 중 재진입해도 기존 핸들을 정리해 최대 1개를 유지한다.
- loop 구간은 0~96000 프레임, 2초 전체다. 엔진 반복 설정을 실제로 확인해야 한다.
- 기존 manifest의 cooldown 120 ms는 루프 종료를 지연시키는 조건이 아니다. 단발 재생 API의 쿨다운에 넣지 않고 위 상태로 제어하는 보완 제안이다.

### 생존 피격
- 실제 유효 피해 적용 후 HP가 양수인 적만 후보로 삼는다. 피해 0, 이미 사망, 누수 퇴장, 무효 표적은 제외한다.
- 직접 공격과 연소 주기 피해의 원인을 구분한다. 연소 주기 피해는 피격음을 억제하고 공용 루프로 표현한다. 처치가 발생하면 기존 처치음 정책을 따른다.
- 동일 시뮬레이션 갱신의 피해를 정리한 뒤 해당 적이 살아 있을 때만 생존 피격 후보를 내보낸다. 같은 갱신에서 뒤이어 죽거나 누수한 적은 피격 후보를 취소한다. 이전 갱신의 이미 재생된 소리를 소급 취소하지 않는다.
- 적별 중복 후보를 합치고 sound ID 전체 100 ms 간격·최대 2 voice를 적용한다. 간격 판정은 가청 폭주를 막도록 단조 실제 시간 기준을 제안한다. 2배속에서도 완화하지 않는다.
- a/b는 재생이 승인될 때만 순차 선택한다. 전투 난수를 소비하지 않는다. 제한에 걸린 후보는 대기열에 쌓지 않는다.
- 프레임 간 HP 차이나 피격 반짝임만으로 원인을 추정하지 않는다. 직접 피해·연소·종결 결과를 구분할 근거가 없으면 이 연결을 보류한다.

공통: 단발은 상태 차단 여부와 무관하게 소비 위치를 전진시켜 재개 시 과거 사건을 재생하지 않는다. 새 런에서는 런 키와 소비 위치를 함께 교체한다. 전체 voice 제한이 찼다면 낮은 우선순위 후보를 버리며 누수·결과음을 밀어내지 않는다.

## 개선 제안과 다른 팀 요청
제안 AU-04-P1: 위 상태 기반 공용 루프와 피해 원인별 필터를 채택 검토한다. 이유는 지속음 중첩·복귀 폭주 억제, 효과는 전투음 가독성 개선이다. 예상 작업량은 현재 사건 정보가 있으면 소규모 연결 및 12시나리오 확인, 없으면 별도 읽기용 관측 지점 검토가 필요하다. 위험은 원인 오분류·종료 누락·과한 억제이며 로그와 청취로 확인한다. 의존성은 두리의 현재 소스·사건 정보다. 게임 규칙 충돌은 없으며 음향 표현 제안이다.

두리/개발1 요청: 현재 빌드에서 장판 생성 식별자·활성 수, 직접/연소 피해 구분, 갱신 끝의 생존/사망/누수 분류, 모든 정지 사유에 접근 가능한지 확인하고 채택/보류를 기록해 달라. AU-02 실행 대조를 위해 승인된 현재 소스 또는 위 항목의 원시 로그와 정확한 빌드 커밋이 필요하다. 공개 요청 기록은 상대의 인수·실행 완료를 의미하지 않는다.
