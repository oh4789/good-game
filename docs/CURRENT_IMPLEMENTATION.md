## 현재 기능과 역사적 기록의 구분

- Android v0.14는 화면 크기와 입력 좌표의 Android 전용 scale 수정이다. 같은 짧은 변390논리 단위로 기존 UI를 배치하며 실제 폰 검증은 별개다. [능력 구매·합성·희귀도 제안](proposals/2026-10-04_ability-shop-merge-rarity-proposal.md)은 미구현·미승인으로 현행 첫 중복/XP 카드 규칙을 대체하지 않는다.

## 이어하기와 이전 버전 주의

현재 Web 런은 v0.13, Android는 v0.14에서 이어한다. 실제 기기 업데이트 뒤 이어하기 보존은 별도 확인해야 한다. QA를 켜지 않은 이전 5·10배 저장은 속도를 최대3배로 제한해 저장하며 다른 진행과 RNG는 유지한다. 저장 schema는 바꾸지 않는다. 2배를 넘는 저장 속도는 v0.8 이하 클라이언트가 읽지 못할 수 있다. v0.8 전환 때부터의 아래 이전 클라이언트 복구 경계도 여전히 주의한다. 기존 런은 기존 타이밍으로 이어진다. v0.7을 단순히 여는 것은 읽기 전용이며 저장을 변경하지 않는다. 다만 새 런 전환이 중단되어 새 저장과 이전 호환 저장이 함께 남으면 v0.7의 복구는 더 이른 진행을 제시할 수 있다. 이를 명시적으로 이어하면 활성 저장이 옛 진행으로 교체될 수 있고, 먼저 보존된 새 저장 바이트가 자동으로 돌아오지는 않는다. 정상 완료된 새 v0.8 런은 v0.7에서 이어하기가 비활성화된다.

## 검수 경계와 다음 인수

v0.13 소스와 정확한 동결 PCK는 각각30/30 suite, 집중 ObjectiveUI888검사, 자연 진행16쌍의 동등성25,632검사와 리소스162검사를 통과했다. 네이티브25쌍 화면의 정확한 PCK 재렌더링 PNG가 소스와 바이트 동일했다. 새 SOURCE 재추출/재import·집중검사와 새 PCK의111개 런타임 payload 동일성도 확인했다. 구체적인 범위와 초기 도구 실패 후 재검증은 [v0.13 보고](proposals/2026-10-03_main-v13-test-handoff-report.md)에 기록했다. v0.12 이하 검증은 각 당시 보고에 보존한다.

**최종 v0.13 브라우저 WASM·IndexedDB·실제 휴대폰·사람의 인지/재미·물리 기기 청취 인수는 열려 있다.** 배포 성공·네이티브 PASS·백업 바이트 일치를 웹/휴대폰 합격으로 바꾸어 쓰지 않는다. APK 생성, 다운로드 페이지 제공, 실제 다운로드, 기기 설치, 실제 기기 인수는 각각 별개 문턱이다. PWA·safe-area·발열·배터리·장시간 성능은 아직 합격 처리하지 않는다.

## 승인된 1차 완성과 다음 우선순위

사용자는 1차 완성까지 진행하도록 승인했다. [1차 완성 인수표](proposals/2026-10-03_first-completion-acceptance.md)가 범위와 남은 검수 기준이다. 사각맵1개·3영웅6갈래·10웨이브 최종 보스·선택/승패/재시작·같은 기기 저장·Android 시험 설치·3–5명 친구 테스트를 작은 완성 게임 범위로 묶는다. **범위 승인과 전체 완료 판정은 다르며 아직 IN_PROGRESS다.**

1. v0.13 보스 목표·도움말 UI 통합과 소스/패키지 검증을 마쳤다. 이 작업 이후 새 기능 추가를 멈추고 남은 인수표를 닫는다. 실제 플레이에서 인지·가독성·조작 문제를 확인하면 해당 문제만 좁게 수정하고 재검증한다.
2. Android 시험 APK의 빌드·전달·설치·기기 검수와 승인된 브라우저의 시작→선택→완주→저장 재개를 각각 확인한다. 실제 touch/Back/배경복귀·작은 화면·음향과 기기/OS/빌드 증거가 필요하다.
3. 현재 모델의 자연 성장·8갈래 조합·배치 비교, 약7분 1배속 활동시간과 별도 세션시간, 3–5명 친구의 보스 인지·배치/카드 선택 이유를 검사한다. 자동화 결과를 사람의 승률·친구 테스트 수로 세지 않는다.

인수 문턱 전에 새 맵·영웅 명단·영구 경제를 확장하지 않는다. [2차 보스 공략·채굴 임무](proposals/2026-10-03_phase2-mission-proposal.md)는 별도 아이디어 제안이며 구현·영구 자원 경제 승인으로 해석하지 않는다. 미해결 접근·실기기·사람 검수는 새 기능 추가로 대신하지 않는다.

새 검수·후속 개발은 현재 전달물·버전을 기준으로 한다. 과거 완료 결과와 팀별 기록은 보존한다. 운영 파일 변경에는 담당·파일·기준 커밋·격리 브랜치·인수 조건을 먼저 확인하며, 현재 Site 최종 통합과 배포는 두리가 맡는다.
