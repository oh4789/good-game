## 실제 실행 결과

환경: Ubuntu24.04, Godot4.6.3, Xvfb, OpenGL Compatibility/Mesa llvmpipe. 오디오는 Dummy.
참고한 실제 소스: scripts/SquareScreen.gd, scripts/SkillDetails.gd, tests/LayoutV04.gd, tests/ResumeUI.gd.
이전 DV2-01 결과 및 기존 LayoutV04의 고정 크기 검수 범위를 읽고, 이번에는 동일 인스턴스의 연속 회전과 입력 위치에 집중했다.

회전 순서: **390×740 → 650×390 → 740×360 → 844×390 → 390×740**.
8개 상태: 배치, 영입 상세, 첫 중복 진급, XP 선택, 도움말, 원정 메뉴, 새 원정 확인, 종료.

| 실행 | 결과 |
|---|---|
| 최종 native 화면·마우스·키보드 | 1,240/1,240 통과 |
| 실제 창 입력 경로 합성 터치·마우스 | 345/345 통과 |
| 초기 headless 화면·마우스 | 1,160/1,160 통과, 최종 합계에 더하지 않음 |

최종 두 하네스는 검사항목이 일부 겹친다. 합계를 고유 시나리오 수나 사람의 플레이 횟수로 해석하지 않는다.
SubViewport.push_input만으로 raw touch를 주입하면 버튼 클릭 변환 경로를 검증할 수 없었다. Input.parse_input_event를 통한 실제 창 경로에서 같은 크기·진급/XP 선택의 열기·닫기·미확정 상태 보존을 통과했다. 이를 실제 휴대폰 합격으로 해석하지 않는다.

확인:
- 크기 변경 전후 전체 런·RNG·UI capture가 동일.
- 회전 후 실제 새 좌표로 마우스/합성 터치 선택 상세를 열고 닫아도 선택·고철·난수 상태를 확정/재추첨하지 않음.
- 도움말·영입·메뉴·새 원정 확인에서 회전 후 Tab 초점이 모달 내부에 유지됨.
- HUD·영웅 카드·선택 카드·모달 버튼 경계 및 검사한 버튼44×44 목표 통과.
- v0.3의 영웅 카드/세 번째 XP 카드 이탈과 종료 글자 가림은 이번 크기에서 재현되지 않음. 이미 존재하는 v0.8 수정의 재검증이며 이번 개발2가 수정한 것으로 집계하지 않음.

스크린샷50장 생성. 9개 대표 원본을 직접 열어 확인했고, 최종 재실행 뒤 XP740×360·결과740×360·세로복귀390×740를 다시 확인했다. 모든50장을 개별 육안 검수했다는 뜻은 아니다. 기하 검사는 전체40회 상태/크기 조합에 실행했다.

## 문제점·한계

이번 검사 범위에서 새 게임 결함은 확인하지 못했다.
실제 모바일 OS 회전, safe-area/DPR, 브라우저 WASM/IndexedDB, 실기기 터치, 스크린리더는 미검증이다.
원정 데이터는 UI fixture로 준비했고 자동 전투를 멈춘 상태에서 검사했다. 자연 완주·밸런스·전체 공격 모션·고승급 무기 끝점 검증이 아니다.
test_mode로 저장을 비활성화했다. 런 snapshot 보존은 실제 디스크/브라우저 저장 성공과 다르다.
회전이 끝난 후 입력을 검사했으며, 손가락을 누른 채 회전하는 도중의 취소·release 동작은 후속 범위다.

## 개선 제안

1. 기존 v0.3 레이아웃 패치3개는 v0.8에 기계적으로 적용하지 않는다. 현재 responsive/result 구현과 중복되므로 기존 패치는 역사적 제안으로 보존한다. 효과: 오래된 패치에 의한 회귀 방지. 작업량S, 위험낮음, 두리의 현행 소스 유지에 의존, 규칙 충돌 없음.
2. 이번 두 전용 하네스를 두리의 회귀 검수 후보로 채택 제안. 회전/입력 변환 회귀를 잡는 데 목적이 있다. 작업량S, 도구 유지비낮음. 운영 파일 수정 없이 실행 가능. 자동 CI 채택은 두리 결정이며 이번에 설정하지 않음.
3. raw touch 직접 주입과 OS/엔진의 입력 변환을 구분해 결과를 기록한다. 하네스10건 실패를 게임 결함으로 전달하지 않는다. 추가 앱 수정안이나 의미 없는 패치는 만들지 않았다.
