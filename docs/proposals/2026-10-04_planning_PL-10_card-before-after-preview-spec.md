## 3. 화면 규칙

상세창 순서는 **이름 → 대상·카드 단계 → 현재/선택 후 수치 → 짧은 효과 설명 → 기존 원정 한정 안내**다. 닫기와 `이 강화 선택` 버튼은 기존 구조를 쓴다. 영웅 승급과 카드 단계는 계속 구분한다.

예시: 탄코의 장전 정비를 1회에서 2회로 올리는 상세창.

| 표시 항목 | 내용 |
|---|---|
| 제목 | 장전 정비 |
| 대상·단계 | 탄코 · 카드 1 → 2 / 3 |
| 현재 | 공격 간격 1.457초 |
| 선택 후 | 공격 간격 1.370초 |
| 해석 | 간격이 짧을수록 빠르게 공격합니다. |
| 기준 안내 | 1배속 기준 수치입니다. 실제 공격은 표적과 전투 상황에 따라 달라집니다. |

- 간격은 **1배속에서 모델이 설정하는 공격 간격**이다. 남아 있는 재사용 대기시간, 실제 프레임 간격, 배속을 적용한 벽시계 시간, 초당 피해량으로 표시하지 않는다. 일반 1/2/3배와 QA 5/10배에서 같은 전후 수치를 쓴다.
- 피해는 기존 명칭 **성장 피해 배율**을 사용한다. 승급·개인·공용 피해 성장분의 합이며, 적 장갑·갈래 배율·명중 수·비비 집중 누적까지 반영한 최종 피해나 DPS가 아니다. 보조 문구: `승급과 카드의 피해 성장분입니다. 실제 피해는 공격 방식과 적 장갑에 따라 달라집니다.`
- 사거리는 게임 내부 수치로 표시한다. 확인하지 않은 m·물리 px 단위를 붙이지 않는다. Android 화면 scale을 사거리 성장으로 환산하지 않는다.
- 개인 카드는 기존 `현재 → 다음 / 3`, 공용은 `반복 현재회 → 다음회`를 유지한다. 공용을 3단계 상한으로 표시하지 않는다.
- 수치와 `현재/선택 후` 글자를 함께 쓴다. 간격 감소도 이점임을 문장으로 알리고 색이나 위/아래 화살표만으로 뜻을 전달하지 않는다.
- 폭이 좁으면 두 값을 세로로 배치한다. 핵심 수치·단계·대상을 말줄임으로 숨기거나 글꼴을 계속 줄이지 않는다. 큰 반복 횟수도 줄바꿈한다. 기존 본문 스크롤과 버튼 접근을 유지한다.

### 공용 카드 상세

첫 줄은 공용 보너스 변화다. 공방 탄약과 공방 조준기는 보유 영웅별 실제 값을 최대 3행으로 덧붙이며, 대기·배치 전 상태를 함께 표시한다. 미보유 영웅의 가상 승급·투자 수치는 만들지 않고 `이후 영입하는 영웅에게도 적용됩니다.`로 설명한다. 방벽 보강은 공유 HP 두 줄만 보여준다.

공방 탄약의 `+8% → +12%`는 **기본 피해에 더하는 공용 성장분 +4%p**다. 현재 피해 전체가 4% 곱해지는 뜻이나 세 영웅의 피해 증가를 합산한 파티 수치가 아니다. 영웅별 성장 배율을 바로 아래에 붙여 이 차이를 확인할 수 있게 한다.

## 4. 계산 규칙과 반영 시점

모든 식은 현재 v0.13 수치다. 별도 밸런스 확정이나 수치 변경 제안이 아니다. `r`은 해당 영웅 승급, `p`는 해당 개인 피해 카드 횟수, `c`는 공용 피해 횟수, `n`은 해당 간격 카드 횟수다.

| 항목 | 현재값과 선택 후 값 | 시점·오해 방지 |
|---|---|---|
| 개인 피해 3종 | 성장 배율 `1 + 0.18r + 0.08p + 0.04c` → 현재값 `+0.08` | 개인 카드의 +8%p. 승급·갈래를 변경하지 않음 |
| 공방 탄약 | 공용 성장분 `4c% → 4(c+1)%`; 영웅별 성장 배율은 `+0.04` | 보유·대기·향후 영입 영웅에 적용 |
| 간격 3종 | `기본 간격 × 0.94^n` → `기본 간격 × 0.94^(n+1)` | 비비 기본/난사 0.18초, 집중 승급1 0.14초·승급2 이상 0.12초; 탄코 1.55초; 로코 2.1초 |
| 개인 사거리 2종 | 비비 `173 + 개인횟수×8 + 공용횟수×4`, 탄코는 기본 180; 선택 후 각각 `+8` | 폭발·화염 반경 증가로 표현하지 않음 |
| 공방 조준기 | 공용 보너스 `4g → 4(g+1)`; 보유 영웅 사거리 각각 `+4` | 로코 기본 사거리 192. 관통 갈래라면 관통 길이도 +4, 폭은 그대로 |
| 오래 남는 파쇄 | 장갑 약화 **부여 지속시간** `3 + 횟수` → `4 + 횟수`초 | 남은 시간에 즉시 +1하거나 약화 강도를 더하는 카드가 아님 |
| 방벽 보강 | 현재 HP `h → h+2`, 최대 HP `m → m+2` | 체력이 가득 차도 두 값 모두 증가. 패배 뒤 부활 효과가 아님 |

공격 간격 표시는 소수 셋째 자리, 성장 배율은 둘째 자리, 사거리·부여 지속시간·HP는 해당 정수 수치로 표시한다. 표시 마지막 단계에서 반올림하며, 표시 문자열이나 반올림한 현재값으로 선택 후 값을 다시 계산하지 않는다. 기획 검산은 십진수 연산의 일반 반올림을 사용했다. 채택 구현에서는 실제 모델 계산값과 이 표의 문자열 예시가 맞는지 확인한다.

**선택 직후부터 모든 진행 중 효과를 다시 계산한다는 뜻은 아니다.**

- 간격 카드는 다음 공격이 대기시간을 새로 설정할 때 적용된다. 이미 남은 `cooldown`을 선택 순간 비례 축소하거나 초기화하지 않는다.
- 피해 카드는 이후 공격 생성에 반영된다. 이미 발사된 포탄·로켓과 기존 화염장의 저장된 피해를 소급해서 키우지 않는다. 탄코 화염은 발사 때 저장된 성장 배율을 사용한다.
- 로코 관통 길이는 발사 시점의 사거리 +180이다. 이미 만들어진 관통 구간을 늘리지 않는다. 폭·추가 표적 수·폭발 반경은 이 카드로 증가하지 않는다.
- 장갑 약화는 로코의 유효 명중 시점에 현재 카드 횟수를 읽어 부여 시간을 정한다. 비행 중 발사체도 이후 명중 시 이 규칙을 따른다. 이미 약화된 적의 타이머가 카드 선택만으로 바뀌지는 않으며, 명중하면 기존 남은 시간과 새 부여 시간 중 큰 값을 쓴다. 무장갑 적에게 장갑 약화 효과가 새로 생기는 뜻이 아니다.

## 6. 상태 보존과 오래된 선택창

표시 계산은 현재 상태를 읽고 가상 횟수 1회를 대입하는 읽기 전용 작업이다. 실제 보상을 임시 선택한 뒤 되돌리는 방법을 쓰지 않는다. 미리보기 때문에 RNG·카드 횟수·HP·투사체·대기시간·이력·저장값을 변경하지 않는다. 기존 창 열기/닫기의 저장 동작을 제거하라는 뜻은 아니며, 계산 자체가 추가 저장을 유발하지 않아야 한다.

채택 시 담당자는 다음을 기존 선택 경로와 함께 보장한다.

1. 현재 보상 단계, 실제 후보 ID·인덱스·`reward_epoch`, 대상 출전 상태와 개인 카드 상한을 확인한 값만 보여준다. 개인 상한 3회에서 4회로 오르는 유효 선택처럼 표시하지 않는다.
2. 확정은 기존 `choose_reward`의 인덱스·epoch 검사와 유효 후보 검사를 통과해야 한다. 미리보기의 숫자나 복제 상태를 실제 게임 상태로 복사하지 않는다.
3. 닫기·재열기·이어하기·연속 보상 전환에서는 실제 확정 상태와 현재 후보로 다시 계산한다. 이전 카드의 계산 결과를 다음 후보에 재사용하지 않는다.
4. 이미 끝난 선택이나 오래된 epoch라면 예전 값으로 확정하지 않는다. 현재 선택 화면을 다시 안내한다. 미리보기 실패를 이유로 후보를 재추첨하거나 다른 카드로 대체하지 않는다.
5. 피해·사거리는 기존 모델 계산을 근거로 파생값을 구한다. 간격은 실제 공격 경로와 표시가 같은 식을 쓰도록 담당자가 계산 경로를 정하고 대조한다. 별도 표시용 상수를 장기간 독립 관리하는 것은 불일치 위험이다.

## 7. 검증 결과와 채택 후 인수 조건

**이번 실행:** 원본 ZIP 크기·SHA256·CRC 확인, 위 네 파일의 정적 대조, Python Decimal로 12종 예시 및 아래 경계값 검산을 수행했다. 카드 ID 12개와 예시의 누락·중복도 대조했다. 게임 엔진·브라우저·APK 실행, 사람의 이해 측정은 **0회**다. 다른 팀의 suite나 실제 플레이 수를 이번 검증 횟수에 더하지 않는다.

| 집중 승급1 비비 간격 카드 2 → 3 | 0.124 → 0.116초 |

## 9. 다른 팀 요청과 다음 단계

요청은 문서에 남긴 인계 항목이다. 직접 메시지 발송·담당 수락·적용 승인을 뜻하지 않는다.

- **두리:** PL10-A는 제안으로 보존하고, 실제 선택 이해도 문제가 확인될 경우 채택/보류와 적용 시점을 판단한다. 채택 시 기준 소스·담당 파일·격리 경로·인수 조건을 지정한다. 이번 기획 완료를 막는 입력은 없다.
- **지정 개발 담당:** 채택 뒤에만 계산 경로·기존 상세창 연결·상태 불변성 증거를 인계한다. 전체 게임 코드나 저장 형식 변경 요청이 아니다. 이 입력이 필요한 후속은 PL10-A 구현 인수다.
- **QA:** [PL-09 최신 기록](2026-10-04_planning_PL-09_v13-intake-and-blockers_v2.md)의 최소 카드 관측과 v0.13 휴대폰 점검 순서를 재사용한다. 실제 빌드·플랫폼·제시 카드·선택 이유·본인이 이해한 효과·화면 문제를 승인된 비공개 경로로 인계한다. 공개 결과에는 개인정보를 넣지 않는다.

다음 후보는 아래 순서이며 현재 실행하지 않았다.

1. **우선순위 높음 — 기존 1차 플레이 기록 인수와 카드 선택 오해 판정.** PL-09 후속과 같은 과업이므로 그 기록을 재사용한다. 이유: 실제로 전후 표시가 필요한지와 1차 완성의 남은 선택 이해도를 판단해야 함. 범위·산출물: 동일 빌드 3–5명 기록에서 오해·미노출·진행 차단과 좁은 수정 우선순위 정리. 완료 조건: 실제 관측 출처와 판단 연결, 자동 원정·다른 빌드 혼합 없음. 의존성: 사용자/QA의 실제 자료. 자료가 없으면 새 설계나 같은 차단 문서를 반복 생성하지 않는다.
2. **후속 — PL10-A 채택 시 실제 표시·모델 결과 대조.** 이유: 계산 예시와 실제 사용자 화면의 일치 확인. 산출물: 이 문서 조건별 반영/불일치/미검증 표. 완료 조건: 담당이 전달한 구현·화면·실행 증거로 판정. 의존성: 두리의 채택·담당 인계와 승인된 검토 빌드. 기획이 운영 파일을 선행 수정하지 않는다.

마지막 완료 지점: 최신 지시·중복 결과 확인 → Web v0.13 원본 대조 → 12종 전후 수치·경계 검산 → 표시·상태 보존·검수 조건 작성. **다음 1단계는 기존 실제 플레이 자료 인수**다. 아직 없는 사람 관측이나 적용 결과를 이 문서의 숫자 예시로 대신하지 않는다. 기존 문서·게임 코드·배포는 변경하지 않았다.
