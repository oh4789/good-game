## 원인과 좁은 수정

v0.3의 고철1/필요8·구매 불가 상점에서 닫기 입력 실패를 원본 소스와 실제 APK 리소스 양쪽에서 재현했다. 프레임 처리를 켜면8프레임 동안 닫기 버튼이8번 숨겨져 native 버튼의 press가 release 전에 취소됐다. 처리를 끈 대조에서는 동작했다. SceneTree 자체가 정지한 문제나 단순 자금 부족이 원인은 아니었다.

SquareScreen의 표시 조건 두 곳에 열린 상점 상태를 포함해 버튼이 프레임 사이 계속 보이도록 했다. 모델·밸런스·구매 비용·저장 schema/경로·현재 진행·기존 취소 입력 규칙은 변경하지 않았다. 과거 UI 시험이 처리를 꺼서 놓친 경계를 새 live-frame 회귀로 보완했으며 모든 플랫폼 검수 공백이 해소됐다는 뜻은 아니다.

## 현재 인수와 Work 우선순위

QA/개발2는 위 v0.3.1 해시를 사용한다. v0.3은 부정 대조/과거 증거용이다. 여러 프레임 동안 버튼을 누른 뒤 release하는 실제 처리 활성 시험을 유지하고 콜백 직접 호출·단일 프레임·처리 중지 PASS로 대체하지 않는다.

사용자 폰에서 업데이트 후 닫기→전투/메뉴 복귀,앱 재실행→Continue,진행 보존을 확인해야 최종 기기 인수를 닫을 수 있다. 현재 **수정 배포됨 / 사용자 폰 확인 대기**다. 앱 삭제·저장 초기화·재설치를 요구하지 않는다. 플랫폼Back·touch 느낌·성능·스피커·브라우저 저장도 미검증으로 유지한다.
