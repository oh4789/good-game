## 4. 이번에 발견한 문구 정합성 쟁점

### PL11-C01 — 처치 성장의 시작점

승인 문서와 v0.1 결과에는 ‘구매 이후’라는 표현이 있다. v0.3 소스는 후보 제시 비용을 낼 때 성장 시작점을 기록하지 않고, **실제로 카드를 선택 확정할 때의 팀 처치 수**를 각 취득분에 저장한다. 카드 본문과 장부는 이미 ‘획득 이후’로 표현한다.

이 차이는 선택창을 닫고 전투를 진행한 뒤 돌아올 때 드러난다. 예를 들어 팀 처치 10에서 후보 비용 결제 → 닫은 동안 15까지 처치 → 전투 기록 카드 확정 → 20까지 처치했다면, 새 취득분의 성장 대상은 **5처치**다. 결제 이후 10처치로 소급하지 않는다.

**문구 명확화 제안:** `이 카드를 선택 확정한 뒤의 팀 처치부터 성장합니다. 후보를 보기 위해 고철을 낸 시점부터 세지는 않습니다.`

판정은 **사양 표현의 모호함**이다. 사용자 오해나 게임 기능 결함을 재현한 것은 아니다. 현재 동작을 유지한 문구 명확화를 권고한다. 결제 시점부터 누적하는 것이 의도라면 두리/사용자의 규칙 판단이 필요하며, 이번에는 계산이나 기존 승인 문서를 바꾸지 않았다.

### PL11-C02 — 두 종류의 공용 효과

상점·도움말에는 ‘공용’이라는 축약이 함께 쓰이지만, 능력 상세의 `해당 영웅 전 성급`과 XP의 `출전대 공용`은 적용 대상이 다르다. 실제 화면에서 사람이 혼동했는지는 미관측이다.

**짧은 표현 제안:** XP는 `출전대 전체`, 유료 능력은 `비비 전 성급`처럼 종류를 붙인다. 이미 정확히 쓰인 상세·장부를 재작성하지 않고, 실제로 혼동이 확인되는 축약 위치만 좁게 보완하는 안이다.

### 이미 반영된 안내

합성 상세에는 1성 적용 해제와 남은·미래 1성의 기록 유지가 함께 있다. 장부에는 현재 적용 인원·각 취득분의 처치 성장·중첩이 나온다. 후보 비용은 한 번이며 상세 확인 후 무료 확정한다는 안내도 존재한다. 이 항목들을 누락으로 다시 요청하지 않는다. 최종 가독성과 이해는 사람 자료가 필요하다.

| 유료 능력의 common과 XP common 각각 선택 | 전자는 해당 영웅 종류, 후자는 출전대 전체. 둘의 적용 범위를 따로 대조 |
| 안정판에서 상세 확인 버튼을 누른 채 입력 취소·중단 | 기존 v0.15 취소 보호를 유지. 새 미리보기 때문에 취소된 입력이 보상을 확정하지 않음 |

검증 범위: 두 압축본의 식별·CRC, 안정판 모델/정의 바이트 비교, 두 계열 소스의 선택·장부·범위·합성·UI 문구 정적 대조, 위 산술 검산. 산술 도구의 최초 구문 오류를 수정한 뒤 최종 검산을 통과했다. 엔진·브라우저·APK·실기기·사람 이해 검수는 이번에 수행하지 않았다.

## 6. 개선안·요청·다음 작업

| 항목 | 예상 효과·작업량 | 위험·의존성·현재 규칙 충돌 |
|---|---|---|
| PL11-C01 확정 이후 문구 | 성장 시작점 해석 통일. 문구 수준의 작은 변경 | 두리의 의도 확인 필요. 현재 동작을 유지하면 규칙 변경 없음; 결제 시점 누적으로 바꾸면 별도 규칙 결정 |
| PL11-C02 적용 대상 이름 | XP 전원 효과와 영웅 종류별 효과 구분. 실제 혼동 위치만 소규모 보완 | 긴 문구의 작은 화면 잘림 위험. 기존 상세 활용과 사람 관측 우선. 새 능력·수치 변경 없음 |
| PL-10 재사용 범위 한정 | 현재 안정판 검산 재사용, 실험판 오표시 예방 | 적용은 두리 채택·담당 인계 이후. 기존 UI 취소 보호와 실험 저장 격리 유지 |

**다른 팀 요청:** 두리는 C01을 현재 동작 기준 문구 명확화로 볼지 검토하고, UI 적용을 채택할 경우 담당·기준 파일을 지정한다. 개발/QA는 이미 보유한 실행 증거를 해당 버전과 연결해 제공하며 같은 자동 검사를 기획 때문에 반복할 필요는 없다. QA/사용자는 실제 플레이의 **버전·플랫폼, 제시 카드 화면, 고른 카드와 이유, 본인이 이해한 효과**를 기존 [PL-09 최소 관측](2026-10-04_planning_PL-09_v13-intake-and-blockers_v2.md)으로 인계하면 PL-11 이해도 판정을 재개할 수 있다. 공개 보고에는 개인 식별 정보·비공개 접근 정보·원본 게임 코드를 넣지 않는다. 요청 게시가 담당의 수락을 뜻하지 않는다.

다음 후보:

1. **우선순위 높음 — 실제 선택 기록 인수 후 PL-11 재개.** 이유: 남은 것은 사람의 이해 증거다. 산출물은 관측에 근거한 오해·미노출·진행 차단과 수정 우선순위. 완료 조건은 실제 카드·선택 이유·이해한 효과의 연결, 안정/실험 버전 분리다. 동일 빌드 3–5명 인수는 기존 1차 기준이며, 먼저 받은 개별 제보도 부분 분석할 수 있다. 자료가 없으면 동일 차단 보고나 새 설계를 반복 생성하지 않는다.
2. **후속 — C01 판단 또는 PL-10 구현 인계가 도착하면 해당 변경만 대조.** 산출물은 문구/실제 계산/화면의 일치 여부. 두리의 판단·담당 결과가 의존성이며, 승인 없이 운영 코드를 바꾸지 않는다.

마지막 완료: 최신 기록 탐색 → 사람 자료 미확보 확인 → 새 안정/실험 소스 인수 → 적용 경계·성장 시작점 대조 → 산술 검산·인계. **다음 1단계는 실제 카드 선택 기록 인수**이며, 이번 사양 대조를 사람의 이해도 합격으로 처리하지 않는다.
