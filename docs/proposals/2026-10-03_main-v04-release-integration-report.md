## 2. 이번 구현

### 같은 런 이어하기와 저장 보호

- 같은 런의 진행을 저장하고 이어가는 기능을 추가했다.
- 저장 내용 검증, 원자적 교체와 백업 복구 경로를 적용했다.
- 손상된 저장 원본은 보존한다. 백업에서 복구한 유효 상태를 손상된 기본 저장으로 덮어쓰지 않도록 보호했다.
- 정상적인 새 런 확인을 반복할 때 불필요한 보관 파일이 누적되어 보관 한도를 소모하지 않도록 처리했다.
- 새 런 확인과 취소를 구분하고, 취소로 기존 진행이 초기화되지 않도록 검수했다.

기존 v0.3 문서의 “최고 웨이브만 저장, 중간 런 이어하기 없음”은 그 버전의 역사적 상태다. **현재 v0.4의 저장 지원 상태는 이 기록을 따른다.** 새 런에서 성장 초기화, 런 밖 영구 전투력 없음이라는 게임 규칙은 유지한다.

### 음향과 화면

- Work v0.3.1의 효과음·BGM 연결을 보존해 통합했다.
- 재생 수 제한이 있는 음성 풀을 사용하고, 신규 설정의 기본 음향 상태는 OFF다.
- 구버전 음향 설정은 읽기 전용으로 가져오며 구버전 저장을 덮어쓰지 않는다.
- 가로 화면, 터치 조작과 동작 줄이기 지원을 보존했다.
- 웹 DPR 어댑터는 실제 CSS 논리 크기에 맞춰 44 CSS 픽셀 조작 영역과 포인터 좌표를 유지하면서 전체 backing 해상도를 사용하도록 구성했다. 이 조정은 네이티브 화면 경로를 변경하지 않는다.
- 웹 어댑터의 실제 브라우저 검증 여부는 아래 미검증 항목과 구분한다.

3영웅·6갈래, 자동 전투, 첫 중복의 즉시 승급·갈래 선택, 이후 중복 성장, 보조 카드와 영입 분리는 변경하지 않았다. 새로 정리한 3영웅 아트는 v0.5 통합 검수 후보이며 현재 배포 완료 상태가 아니다.

## 4. 이번 배포 패키지의 검수

최종 소스와 배포 패키지를 기준으로 다음 검수를 수행했다.

| 검수 | 확인 범위 |
|---|---|
| 최종 패키지 검증 | 2,521개 검증 항목 |
| 전체 런 | 직접 실행 8회와 저장 후 재개 8회, 총 16회 |
| 강제 종료와 재시작 | 실제 SIGKILL·재시작 26회 |
| 새 런 확인 반복 | 저장 계층 100회와 실제 화면 경로 100회, 총 200회 |
| 새 런 취소 반복 | 취소 100회 |
| 컴파일 결과 대조 | 컴파일된 .gdc 14개와 project.binary가 독립 재컴파일 결과와 바이트 일치 |
| 화면 밀도 | 현행 또는 변경 없는 부위의 네이티브 캡처 근거 확인 |

2,521개는 최종 패키지의 명시된 8개 검증 그룹 합계다. 전체 런의 상태·난수 체크포인트 1,016개, 강제 종료와 확인·취소 횟수는 별도 관측 축이다. 컴파일 대조는 14개 스크립트와 project.binary의 15개 해시 비교이며, 14개의 별도 플레이 테스트가 아니다.

밀도 어댑터의 이전 461개 검증을 최종 PCK에서 모두 다시 실행했다고 집계하지 않는다. 변경 없는 어댑터·배치에 대한 이전 근거와 별도 확인한 최종 확인창 문구를 구분했다. 네이티브 이미지 근거는 현행 또는 변경 없는 부위 124개이며, 이전 확인창 문구의 폐기된 8개 캡처는 제외했다.

각 행은 검수 종류별 기록이다. 검증 항목 수와 런·재시작 횟수를 서로 다른 사용자 플레이 수처럼 더하지 않는다. 통과한 패키지 검수가 브라우저나 실제 휴대폰 검수를 대신하지 않는다.

## 5. 아직 확인하지 못한 범위

이번 환경에서는 Chromium이 소켓 생성 단계에서 EPERM으로 실행되지 않아, 다음을 v0.4에서 독립 검증하지 못했다.

- 실제 브라우저의 WASM 전체 플레이
- 브라우저 IndexedDB 저장·이어하기·재접속
- 실제 휴대폰 터치, 성능, 발열과 화면 동작
- 실제 출력 장치에서의 주관적 믹스·반복 청취 품질

[개발1의 v0.3.1 브라우저 검수](2026-10-03_dev1-v031-integration-report.md)는 그 버전의 증거로 보존한다. v0.4 브라우저 합격으로 옮겨 적지 않는다.

Android 준비 검토에서는 SDK와 내보내기 템플릿이 확인되지 않았다. APK 생성·Android 실기 검수 완료 상태가 아니다.
